8 ranks 的 AllReduce：busbw=1.75×algbw，不是压缩收益At 8 ranks, AllReduce busbw=1.75×algbw, not compression

algbw [GB/s] = size_MB / time_ms [decimal MB and ms cancel to GB/s]
AllReduce busbw = algbw × 2(n−1)/n
AllGather / ReduceScatter / AllToAll busbw = algbw × (n−1)/n
Broadcast / Reduce / SendRecv factor = 1

默认消息 1,000 MB、20 ms：algbw=50 GB/s；8 ranks AllReduce busbw=87.5 GB/s。busbw 是标准化通信指标，不是「网络凭空超出线速」。AllGather/ReduceScatter 的 S 要用总数组大小，不是每 rank 的单块。Default 1,000 MB in 20 ms: algbw=50 GB/s; 8-rank AllReduce busbw=87.5 GB/s. Bus bandwidth is a normalized collective metric, not magical wire speed. For AllGather/ReduceScatter, S is the total array, not one rank's shard.

单端口网络效率预算不能直接套到所有 GPU 集合通信：操作可能走 NVLink、多个 NIC、PCIe 或混合路径。若指标超过选定预算，先核对路径、方向、总消息定义和轨数，而不是自动宣告测量错误。One-port network budgets do not apply automatically to every GPU collective; paths may use NVLink, multiple NICs, PCIe or a mix. If a metric exceeds the selected budget, check path, direction, size definition and rails before declaring an error.

ECN 是提前减速，PFC 是逐跳急刹，DCQCN 是端点反馈控制ECN signals early, PFC brakes a hop, DCQCN controls the sender

传统 lossless RoCE 基线：交换机队列到 ECN 区间先标记 CE；接收端 RNIC 产生 CNP；发送端 RNIC 的 DCQCN 降速，再逐步恢复。如果队列继续逼近溢出，PFC 按 priority 对上游链路发 pause；低于 Xon 再恢复。标记/减速不是丢包；PFC 不是端到端拥塞控制。Classic lossless-RoCE baseline: the switch marks CE as queues enter the ECN range; the receiver RNIC emits CNP; sender RNIC DCQCN reduces rate then recovers. If queues keep nearing overflow, PFC pauses an upstream priority on a hop, resuming below Xon. Marking/rate reduction is not packet loss; PFC is not end-to-end congestion control.

阈值滑块是概念图，不是厂商配置。ECN/PFC/DCQCN 不是所有现代以太网 fabric 的唯一有效组合；替代拥塞控制、receiver credits 与可承受丢包的实现要按协议和负载验证。避免 PFC 死锁、head-of-line blocking，并启用可验证的 watchdog 与遥测。Threshold sliders illustrate concepts, not vendor configuration. ECN/PFC/DCQCN is not the only valid modern fabric design; alternative congestion control, receiver credits and loss-tolerant implementations need protocol/workload validation. Address PFC deadlock/HOL blocking with verified watchdogs and telemetry.

RDMA 是否完全不使用 CPU？Does RDMA avoid the CPU entirely?

数据面可以绕过 host staging，但连接建立、内存注册、页固定、队列配置、控制与错误处理仍需要 CPU/驱动。GPU-initiated 通信也不取消全部控制平面。Payload can bypass host staging, but connection setup, registration, pinning, queues, control and errors still involve CPU/drivers. GPU-initiated communication does not remove all control-plane work.

NCCL busbw 可以跨不同 rank 数直接比较吗？Can NCCL busbw be compared across rank counts?

可以作为标准化参考，但必须同操作、消息大小定义、路径、拓扑、dtype、warmup、迭代窗口与错误状态；小消息看 latency，大消息看带宽，并用实际训练/推理负载复验。It is a normalized reference, but compare the same operation, size scope, path, topology, dtype, warmup, iterations and error state. Use latency for small messages, bandwidth for large ones, then verify real workloads.
