7 / 7 · MY TAKE ARCHITECTURAL GUIDANCE

When to Adopt Phase 111 Kernel, Runtime & KV Fabric Upgrades

✅ Good Fit
  • Long-Context Sparse MLA Training (`64K–128K`): Enable `gather_bwd_recompute_p=True` + `gather_bwd_token_chunk=4096` on SM100 to save `32 GiB` of saved `p` and `30 GiB` of `dS` transient per layer.
  • Hybrid Mamba+Attention & SpecForge MLA Serving: Use vLLM geometry-keyed `copy_kv_cache_blocks_inplace` and SGLang DFlash slot-0 prefix masking.
  • Multi-Turn RL Rollouts on DP Engines: Use verl `crc32(session_id) % dp_size` sticky DP pinning to lift prefix-cache hit rate up to `0.93`.
  • Paged Arena KV Offloading: Combine NIXL base+offset `cuObject` RDMA token minting with LMCache 2-D `cudaMemcpy3DBatchAsync` for block-outermost KV caches.
⛔ Not For
  • Helix CP + Attention-DP with `pp_size > 1`: `align_gen_admission_across_cp` currently runs only in `pp=1` executor loops (`pp_size > 1` raises `ValueError`).
  • KVCacheAwareADPRouter under Helix CP: Disabled because each CP rank probes only its own KV slice, which can cause divergent DP routing.
  • Unregistered Destination Buffers over RDMA: Mooncake direct zero-staging into unregistered CUDA memory applies only to `"nvlink"`; `"rdma"` still requires `register_buffer()`.
  • HND or Blocked-Scale KV Layouts in LMCache 2-D Copy: Only token-major block-outermost layouts with constant layer pitch qualify; HND stays on the kernel path.
