Precomputed Ref Logprobs, `cu_seqlens` Packing & Fused Loss

// 1. Precompute constant reference logprobs ONCE (8 bytes/sample!) // & unload pi_ref BEFORE allocating AdamW states (-17.5 GB/GPU!): batch["ref_chosen_logps"], batch["ref_rejected_logps"] = precomputed_cache[idx]
↓ Ragged `cu_seqlens` Pack + FusedLinearDPOLoss (<answer>)
// 2. Pack chosen (512) + rejected (4096) into 1D ragged [1, 4608, D] hidden = policy_backbone(packed_input_ids, cu_seqlens=cu_seqlens) // 3. Tile lm_head in SRAM without materializing [4608, 152064] logits: loss = FusedLinearDPOLoss.apply(hidden, lm_head.weight, packed_labels, ref_chosen_logps, ref_rejected_logps, beta=0.1)
Saves 17.5 GB (`pi_ref`) + 17.3 GB (`[N, V]` logits) + 2.4 GB (pad activations).

7 / 7 · MY TAKE

Good Fit vs Not For & Production Readiness

✅ Good fit
• Full-parameter and LoRA `DPO / IPO / KTO` preference alignment
• Long-chain-of-thought preference pairs with high length asymmetry
• Large-vocabulary (`128K–256K`) models where `[2B, L, V]` logits OOM
⛔ Not for
• Keeping a frozen full-weight `pi_ref` loaded in HBM during multi-epoch DPO
• Padding `chosen` and `rejected` to `max(L_w, L_l)` along the batch dimension
CSP self-contained · Zero external assets · Ready for main branch archive.
