2 / 7 · SCENARIO: RUBIN SM107A GDN DECODE & VLLM TOP-K NAN ORDERING Deep Dive · 3 Core Decisions

Cutting Warp Instructions by 38% + Die-Local uGPU Pools Lifts VR200 GDN Bandwidth from 62% → 88% (`516.5 us` at `B=2048`)

Input Scenario: (1) VR200 (212 SMs = 2×106-SM dies, 19.15 TB/s DRAM) running BF16-state GDN decode (HV=64, HQ=HK=16, K=V=128, B=2048 -> 8.59 GB state read+write); (2) vLLM cooperative_topk / persistent_topk / sampled_topk with >top_k NaN logits.
Decision 1 · VR200 `ugpu_state_pool` Locality-Domain Binding (`#6604`)
choice Act automatically
Ordinary `cudaMalloc` interleaves pages across both dies (~50% cross-die traffic, capping copy at 68%). Allocating `[pool, HV, 2, 64, 128]` via `CU_MEM_LOCATION_TYPE_DEVICE_LOCALITY_DOMAIN` pins half `t` to Die `t` DRAM + `106`-SM green context, reaching 88% of 19.15 TB/s (516.5 us vs 726.7 us, 1.41×).
Decision 2 · Rubin MLA NVFP4 Runtime PDL Gate `pdl_for(plan)` (`#7004`)
score Act automatically
On 208-SM Rubin (`54` single-wave cluster units), enabling PDL when `items <= 54` (`max_splits=4`) overlaps the merge preamble (`enable_pdl=True`, 100% single-wave fit), whereas `items = 55` disables PDL so merge CTAs never steal SMs from wave-2 decode clusters.
Decision 3 · vLLM Top-K Opaque Inline PTX `mov.b32` (`#63118`)
choice Act automatically
Replaces `__float_as_uint(x)` bit-or with `asm("mov.b32 %0, %1;" : "=r"(bits) : "f"(x))` so `nvcc` cannot lower it to FP `-|x|`, keeping quiet `NaN` at key 0xFFC00000 above `+inf` (0xFF800000) across all 3/3 top-k kernels (100%).
Key Architectural Mechanism: In `gdn_decode_bf16_state_rubin.py`, matching the `cp.async` tile load layout (`g, g+8, ...`) with the compute warp-group layout eliminates CTA-wide `bar.sync`, while `prefetch.global.L2::evict_last` prefetches `pf_dist = 212 * 25 // 3 = 1766` tiles ahead.

7 / 7 · MY TAKE · ARCHITECTURAL FIT & PRODUCTION READINESS Decision Guide · Phase 69

Adopt Locality-Domain State Pools on Multi-Die GPUs & Enforce Master-Thread TMA S2G Waits Across Ring Buffers

Actionable synthesis for AI infrastructure architects deploying linear-attention decode on Blackwell/Rubin, disaggregated KV caches with MoE auxiliary outputs, and MXFP8/NVFP4 quantization pipelines.

✅ Good Fit (When to Adopt Immediately)

  • Multi-Die GPU State Pools (`sm_107a` VR200): Allocate recurrent/GDN state pools with `CU_MEM_LOCATION_TYPE_DEVICE_LOCALITY_DOMAIN` (`ugpu_state_pool`) when `B * HV >= 512`, eliminating the ~50% cross-die fabric penalty (`68% → 88%` HBM utilization).
  • Single-Wave Runtime PDL Gating: Gate `enable_pdl = (max_splits > 1 and items <= units)` in split-K / MLA decode so merge kernels overlap tail drains without stealing SMs from wave-2 decode clusters.
  • Fused RMSNorm + MXFP8 Swizzled Scales: Use TE's 128-aligned `rmsnorm_fwd_mxfp8` with `with_gemm_swizzled_scales=True` to produce rowwise + colwise E8M0 scales in `128×4` macro-tiles without a separate swizzle kernel.
  • Offline KV Capacity Sizing (`trace-analyze`): Replay production OTLP `mp.request.trace` spans (with `request_id` preemption deduplication) across `(chunk_size, capacity)` grids before provisioning DRAM/DFS tiers.

⛔ Not For / Anti-Patterns to Avoid

  • Forking Green-Context Streams on Tiny Eager Batches: Do not fork/join dual-die streams in eager mode when `B * HV < 8192`; the ~5 us CUDA event overhead outweighs parallel launch gains (run back-to-back on caller stream instead).
  • C++ Bit-Or Sign Flips on `__float_as_uint(x)`: Never rely on `bits | 0x80000000u` for total float ordering in CUDA without an opaque PTX `mov.b32`; `nvcc` lowers it to FP `-|x|` and corrupts `NaN` keys.
  • Non-Master `cp_async_bulk_wait_group_read`: Never call bulk async-group waits on worker threads or omit the subsequent `__syncthreads()` before reusing TMA S2G ring-buffer slots.
  • Implicit `DTensor.from_local` on Uneven Shards: Never omit `shape=p.shape, stride=p.stride()` when materializing offloaded EMA tensors under FSDP2 when dimensions may not be divisible by `world_size`.
