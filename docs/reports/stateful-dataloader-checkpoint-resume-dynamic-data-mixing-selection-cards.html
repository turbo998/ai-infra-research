Preventing Copy-on-Write OOMs

In Python `multiprocessing` (`fork`), mutating refcounts on a `64 GB` NumPy/PyTorch index array across 8 workers triggers OS Copy-on-Write page duplication (`512 GB` host RAM OOM). Feistel ciphers use `<1 MB`.

Monotonic Domain Annealing

Because `c_math(t)` and `c_code(t)` advance monotonically whenever sampled, increasing Math weight from `10%` to `25%` at 12T tokens never repeats a single previously seen Math problem.

Robustness Verdict: S5 guarantees bitwise-exact data lineage across arbitrary checkpoint restarts, worker counts, and elastic cluster resizes.

Architect's Verdict: Mandate S5 (O(1) Seek + Feistel + Per-Domain Cursors) for All Pretraining & CPT Pipelines

Production decision guide for building fault-tolerant, curriculum-ready data pipelines.

✅ Good Fit (When to Adopt)

  • Multi-Trillion-Token Pretraining & CPT: Eliminates 34.5-min recovery stalls and prevents 18.4% duplicate-token loss spikes.
  • Multi-Stage Curriculum Annealing & DoReMi: Adjust domain ratios live without rewriting 80 TB of disk shards (+6.8 pts accuracy).
  • Elastic Fault-Tolerant Clusters: Global logical cursors enable 0.0%-overlap rescaling when faulty nodes are drained.

⛔ Not For (When to Avoid)

  • Unindexed Stream-Compressed .jsonl.gz Files: Convert to indexed `.bin+.idx`, `MDS`, or `Lance` shards before training.
  • Tiny Single-Node LoRA Runs (<1 Hour): Standard in-memory DataLoader suffices.
  • Pure On-Policy RL Rollout Buffers: Ephemeral rollouts are generated and consumed in-memory per step.
