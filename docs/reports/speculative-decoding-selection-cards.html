score Act automatically · Confidence 0.90

noul Confirm · Confidence 0.78

Threshold Gating 规则

当活跃并发 Batch Size ≤ 32 时默认开启 EAGLE-3 / MTP（获得 1.58x~3.02x 加速）；当 Batch Size ≥ 48 时自动旁路草稿头，避免废稿消耗饱和的 Tensor Core 算力。

Failure Analysis (`✕` 失守根因)

当 B × (γ + 1) = 64 × 5 = 320 Tokens/step 跨过 GPU 算力屋脊点（205.5 FLOP/Byte）后，校验耗时随候选 Token 数线性增长，被拒绝的草稿直接变成纯算力浪费。

为什么全被拒绝也不会“少算一个 Token”？

  • 保底 Bonus Token 机制: 即使第 1 个草稿 Token d_1 被拒绝，主模型在第 1 个位置的真实概率分布 p_1(x) 已经在并行前向中算出来了！采样器直接从残差分布中重采样出正确的 x_{t+1}，每步至少推进 1 个 Token（若 4 个草稿全中，还能额外白送第 5 个 Bonus Token）。

7 / 7 · MY TAKE · GOOD FIT VS NOT FOR & READINESS ARCHITECT PLAYBOOK

架构师选型决断：全场景标配 EAGLE-3 / MTP + 动态 Batch 门限，代码/RAG 零显存白拿 N-Gram 加速

投机解码是唯一能在 100% 保持原模型精度不降级 的前提下将低并发 Decode 速度提升 2~3 倍的架构利器，但必须配合动态 Batch Size 熔断门限使用。

✅ Good Fit (强烈推荐适用场景)

  • Tier 4 (`EAGLE-3 / DeepSeek-MTP` + 动态门限): 在线交互式 Agent、实时语音对话、代码生成与长思维链推理（+1.2 GB 显存换取 3.02x 单流提速，BS=32 仍快 1.58x）。
  • Tier 2 (`Prompt Lookup N-Gram`): 显存已满（0.0 GB 预算）的 IDE 代码改写 (Diff/Edit)、合同原文抽取、结构化 JSON 转换（白拿 2.24x 提速）。
  • Tier 1 (`gamma=0` 动态退回): 离线大批量数据处理或在线并发 BS ≥ 48 的算力饱和窗口。

⛔ Not For (严禁误用边界)

  • 严禁在高并发 (BS ≥ 48~64) 下不设门限常开投机解码: 算力饱和区验证废稿会导致总吞吐倒退至 0.78x~0.92x。
  • 严禁在已有 EAGLE-3 / MTP 头的模型上额外部署 14GB 独立 7B 草稿模型: 多耗 11.7 倍显存且单流速度反而慢 37.8%。
  • 严禁对自由创作或开放数学推理单独依赖 Prompt Lookup N-Gram: 输入输出无重复词组时接受长度仅 1.15。
