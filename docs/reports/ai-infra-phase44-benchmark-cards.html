Production-Ready for Blackwell/Hopper MoE Serving, GLM-5.2/5.3 Sparse Attention & Full-Iteration CUDA-Graphed Training

✅ Good Fit

  • Blackwell (B200/B300) DeepEP Low-Latency MoE: `mxfp8_grouped_quantize(..., backend="cuda")` and `silu_and_mul_mxfp8_experts_quantize` when `mask[E]` is sparse/skewed.
  • Hopper (H20/H200) FP4 MegaMoE: H200 EP8 push dispatch (`M <= 32`, or `M <= 64` rotated pool on DeepSeek-V4-Pro) with power-of-two global scale rebalancing (`6 * scale <= 448`).
  • PD Disaggregation & Sparse MLA: SGLang Mooncake auto-recovery (`30s–300s` backoff) and TRT-LLM `GLM-5.3-Flash` native FP8 `glm_kpool` decode (`1..128` heads).
  • Full-Iteration CUDA Graph Training: Megatron `FullIterationGradCopy` + MFSDP v2 `ExecutionOrder`.

⛔ Not For

  • Pre-SM100 GPUs for Masked MXFP8 Kernel: `cvt_fp16_to_mxfp8_expert` requires `__CUDA_ARCH__ >= 1000` hardware instructions.
  • Large-Batch H200 MegaMoE Push (`M > 64` or `BLOCK_M > 24`): Push dispatch loses `0.89x–0.95x` at `M=256`; keep the pull barrier path above `M=64`.
  • Raw Unrebalanced NVFP4 Checkpoints on SM90 MegaMoE: Passing raw scales with `6 * scale > 448` silently saturates E4M3 decode without per-expert `global_scales`.
  • 2D `kpool_update` with Packed Context `request_ids`: Same-pool skip requires consecutive positions per table (`positions.dim() == 2` requires `request_ids is None`).
