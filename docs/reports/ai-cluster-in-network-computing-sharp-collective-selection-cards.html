✅ 为什么省出 16 个 GPU SM 对重叠 (Overlap) 至关重要？
当通信与计算重叠执行时，如果 NCCL 抢走 20 个 SM（占 H200 的 15.2%），同时正在跑的反向传播 `cuBLAS GEMM` 就会因缺少 SM 和寄存器带宽掉速 12%~18%！NVLS+SHARP 只用 4 个 SM！
✕ 什么时候需要临时关掉 SHARP 改回 Ring？
做 0-ULP 逐比特对齐的数值静默错误排查（Golden-Step Verification）时，为避免交换机动态到达顺序引发尾数最后 1 bit 舍入差异，可临时固定 `Ring`。
Matrix Summary: Moving floating-point reduction from GPU SMs into NVSwitch and IB switch silicon halves network bytes (`2.0× → 1.0×`), reclaims 16 SMs/GPU, and boosts 2,048-GPU MFU by +14.1 percentage points.

🔍 为什么 MoE 模型的 All-to-All 不能直接用 SHARP？
SHARP 是规约（Reduction/Sum）与广播引擎，适合梯度求和（AllReduce/ReduceScatter）；而 MoE 的 `All-to-All` 是点对点路由个性化 Token（不相加），需靠 `DeepEP` + 自适应路由 AR（Round 2/9）优化！
