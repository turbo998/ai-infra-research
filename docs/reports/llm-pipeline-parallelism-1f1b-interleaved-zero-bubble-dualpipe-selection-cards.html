Good Fit vs. Not For: Choose ZB-V for Dense LLMs and DualPipe for Cross-Node MoE

Actionable decision rules for AI Solution Architects configuring 3D/6D distributed training.

✅ Good Fit (When to Adopt Tier 4 / Tier 3)

  • Cross-Node Large MoE Pretraining (Tier 4 DualPipe): Mandatory when EP ≥ 16 across nodes to overlap heavy All-to-All RDMA with opposite-stream GEMMs (58.4% MFU).
  • Multi-Node Dense LLM Pretraining (Tier 3 Zero-Bubble ZB-V): Optimal for 70B–405B Dense models—shrinks bubbles to 1.8% with balanced 32GB activation memory and zero extra weight copies.
  • Tight Global Batch Size Regimes (Tier 3 / Tier 4): Maintains high MFU even when microbatch count $M$ is close to $P$ or $2P$.

⛔ Not For (When to Avoid)

  • Naive GPipe in Any Production Run (Tier 1): Stashing all $M$ microbatches causes immediate HBM OOM or crippling recomputation.
  • Standard 1F1B on Large Cross-Node MoE (Tier 2): Leaves 34.8% of GPU time idle on bubbles and exposed All-to-All stalls.
  • Single-Node 8-GPU Training: Inside a single NVLink domain, use FSDP/ZeRO-1 + TP without pipeline parallelism.

Day-1 Production Pipeline Parallelism Checklist

1. Enable wgrad_deferral to split linear backward into critical-path B ($\nabla_x$) and deferred filler W ($\nabla_W$).
2. Select ZB-V for Dense models and DualPipe ($M \ge 2P$) for cross-node MoE models.
3. Pair DualPipe with 0-SM / low-SM DeepEP IBGDA RDMA kernels so communication does not steal Tensor Core SMs.
4. Balance Stage 0 (Embedding) and Stage $P-1$ (LM Head + MTP loss) layer counts to prevent boundary stage stragglers.
