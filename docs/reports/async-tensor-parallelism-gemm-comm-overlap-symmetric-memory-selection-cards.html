# 1. 前半场 (AllGather + GEMM): 第 0ms 立即用全部 132 个 SM 算本地分片，0-SM Copy Engine 后台拉取邻居分片
symm_buf = torch.distributed._symmetric_memory.empty((8, M_shard, K), dtype=torch.bfloat16, device="cuda")
hdl = torch.distributed._symmetric_memory.rendezvous(symm_buf, group=tp_group)

# Chunk 0 (本地已有): 0.0ms 零等待启动满血 132-SM GEMM！同时在 dma_stream 启动 Chunk 1 跨卡拉取
out_chunks[my_rank] = torch.mm(x_local_shard, weight_col_parallel)
for step in range(1, 8):
    src_rank = (my_rank + step) % 8
    with torch.cuda.stream(ce_dma_stream):  # 走硬件 Copy Engine DMA (占用 0 个 GPU SM！)
        symm_buf[src_rank].copy_(hdl.get_buffer(src_rank, (M_shard, K)), non_blocking=True)
    compute_stream.wait_stream(ce_dma_stream)
    out_chunks[src_rank] = torch.mm(symm_buf[src_rank], weight_col_parallel)
↓ 后半场 (GEMM + ReduceScatter): CUTLASS Epilogue 内联 PTX multimem.red (<answer>) ↓
// 2. 后半场 (Row-Parallel GEMM + ReduceScatter): 算完每个 Tile 直接由 NVSwitch 芯片硬件累加
CUTLASS_DEVICE void fused_multimem_reduce_scatter_epilogue(bf16x2 reg_acc, void* nvls_multicast_ptr) {
    // 直接从 Tensor Core 寄存器发往 NVSwitch 多播地址，0 通信 SM 占用，省去本地 HBM 往返读写！
    asm volatile("multimem.red.relaxed.sys.global.add.v4.bf16x2 [%0], {%1, %2, %3, %4};"
                 :: "l"(nvls_multicast_ptr), "r"(reg_acc.x), "r"(reg_acc.y), "r"(reg_acc.z), "r"(reg_acc.w));
}

✅ Good Fit (强烈推荐场景)

  • • 70B~405B 大模型 TP=8 / TP=16 预训练与后训练 → Tier 4：单层提速 `1.40x~1.61x`，MFU 冲上 61.7%。
  • • FP8 / NVFP4 低精度训练与长文本 Prefill 推理 → Tier 4：矩阵乘越快，掩盖 TP 通信带来的加速比越大。

⛔ Not For (严禁踩坑场景)

  • • 严禁在 TP+SP 训练中保持默认串行不开启重叠 (Tier 1)：会白白损失近 30% 的算力时间。
  • • 严禁在并发流中开启占用 20+ 个 SM 的传统 Ring NCCL 核函数与 GEMM 抢资源 (Tier 2)：破坏波次量化得不偿失。
