✅ 为什么 3FS 选用 FoundationDB 管元数据？
传统 Lustre MDT 是单命名空间锁瓶颈；3FS 将目录树与 Chunk 路由存入分布式事务 KV 数据库 FoundationDB（支持严格可串行化快照隔离 SSI），元数据节点完全无状态且可水平扩展！
✕ 为什么三副本 (3FS) 需要搭配对象存储分层？
3FS 三副本磁盘空间利用率为 33.3%，因此热盘只存“当前训练集 + 最近 3 个 Checkpoint + 在线 KVCache”，历史归档 Checkpoint 必须异步沉降到廉价 S3。
Matrix Summary: DeepSeek 3FS achieves 91.7% of raw network line rate (6.60 TB/s out of 7.20 TB/s) and saves $1.48M in 3-year software licensing compared to commercial SDS.

hf3fs_iovcreate(&iov, mount_point, /*size=*/1ULL << 30, /*block_size=*/0, /*numa=*/0);
struct hf3fs_ior ior;
hf3fs_iorcreate(&ior, mount_point, /*entries=*/1024, /*for_read=*/true, /*io_depth=*/0, /*numa=*/0);

// 2. 批量压入 64KB 随机块读取请求 (KVCache 换页 / DataLoader 采样，零内核态阻塞)
for (int i = 0; i < batch_blocks; ++i) {
  hf3fs_prep_io(&ior, &iov, /*read=*/true, iov.base + i * 65536, fd, offsets[i], 65536, user_data[i]);
}
hf3fs_submit_ios(&ior); // 敲响共享内存信号量通知本机守护协程 -> 就近挑选 CRAQ Clean 副本发起 RDMA Write

// 3. 轮询完成环收集结果 (远端 NVMe 已通过 io_uring+O_DIRECT+RDMA 直接写妥数据)
struct hf3fs_cqe cqes[64];
int done = hf3fs_wait_for_ios(&ior, cqes, 64, /*min_results=*/batch_blocks, /*timeout=*/NULL);

🔍 为什么 AI 负载会彻底击穿 OS Page Cache？
大模型预训练每个 Epoch 都会对数亿条样本做全局随机排列（Global Shuffle），任何刚读进内存的 64KB 页在被第二次访问前早已被挤出内存，Page Cache 变成纯负资产！
⚡ 把省下来的客户端 DRAM 留给谁？
关闭文件系统 Page Cache 后，每台计算节点腾出的数百 GB 主机内存可直接交由 Mooncake / LMCache 作为显式受控的 KVCache L2 固定内存池（Pinned Pool）！
Robustness Conclusion: Page-cache-free direct RDMA I/O (`O_DIRECT + USRBIO`) is immune to working-set size inflation, holding 6.58–6.60 TB/s from 1 TB to 500 TB.

7 / 7 · MY TAKE · GOOD FIT VS NOT FOR & PRODUCTION READINESS Architect Decision Guide

架构师总结：大模型原生研发上 DeepSeek 3FS，政企交钥匙上 WEKA/VAST GDS

坚持“热层全闪并行文件系统（3FS/WEKA）+ 冷层纠删码对象存储（S3）”双层分级架构，兼顾 6.6 TB/s 极限带宽与 PB 级低成本归档。

✅ Good Fit (强烈推荐场景)

  • • AI 原生大模型训练与 KVCache 卸载池 → Tier 4 (DeepSeek 3FS)：CRAQ 全副本并发读 + USRBIO 零拷贝环跑满 91.7% 线速（6.6 TB/s），P99 仅 0.42ms，3 年省 $148 万软件授权费。
  • • 金融/车企/政企交钥匙生产集群 → Tier 3 (WEKA / VAST GDS)：开箱即用 GPUDirect Storage、N+2 纠删码（85%+ 空间有效率）、多租户硬隔离与 7×24 原厂维保。
  • • 冷热分层生命周期架构：热盘仅保留最近 3 个 Checkpoint 与当前 Epoch 数据，历史归档异步沉降 S3。

⛔ Not For (严禁踩坑场景)

  • • 严禁用通用 NAS / CephFS (Tier 1) 跑千卡主训练或 KVCache 卸载：Primary OSD 串行读瓶颈浪费 2/3 NVMe 带宽，18.5ms P99 直接拖垮在线推理。
  • • 严禁在 500TB 随机 Shuffle 训练中开启 OS Page Cache：缓存命中率 <0.4%，反而引发内核 LRU 自旋锁雪崩使吞吐暴跌 55.8%。
  • • 严禁将 FoundationDB 元数据与大块数据混部在同一 SSD Namespace：10TB Checkpoint 突发写放大将严重阻塞全局 open()/stat()。
