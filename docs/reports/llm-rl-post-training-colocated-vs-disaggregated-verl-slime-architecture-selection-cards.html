85% Watermark Partial Rollout Prefix Freeze & Token-Level Importance Sampling (TIS)
# 1. Slime / AReaL Partial Rollout Continuation at 85% Batch Completion Watermark
def step_rollout_with_partial_continuation(sglang_engine, active_reqs, watermark=0.85):
    completed, paused_for_next_step = [], []
    while len(completed) < int(len(active_reqs) * watermark):
        sglang_engine.decode_step()
    for req in active_reqs:
        if req.is_finished():
            completed.append(req)
        else:
            # Pause in-flight 32K trajectory: preserve generated tokens & behavior_logprobs!
            paused_for_next_step.append(req.freeze_partial_state())
    return completed, paused_for_next_step

# 2. Token-Level Importance Sampling (TIS) Correcting Multi-Step Policy Shift (theta_old -> theta_curr)
def compute_tis_grpo_loss(curr_logprobs, recorded_behavior_logprobs, advantages, c_tis=2.0):
    # Each token t uses the exact behavior policy logprob from the step when token t was emitted!
    token_ratio = torch.exp(curr_logprobs - recorded_behavior_logprobs)
    clamped_tis_ratio = torch.clamp(token_ratio, max=c_tis)
    return -(clamped_tis_ratio * advantages.unsqueeze(-1)).mean()
Deterministic Verifier: Because `recorded_behavior_logprobs[t]` tracks the exact policy version $\theta_{t}$ that generated token $t$, multi-step partial rollouts converge without off-policy instability.

7 / 7MY TAKE · GOOD FIT VS NOT FOR & PRODUCTION READINESS
Architect Verdict: Use verl 3D-HybridEngine for <8K GRPO; Use Slime/AReaL Partial Rollout for 32K+ CoT

✅ Good Fit (When to Use Tier 3 / Tier 4)

  • 16K–64K Long-CoT Math/Code RLVR & Multi-Turn Agents (Tier 4): `Slime / AReaL` Partial Rollout + TIS eliminates the 140s straggler tail wait.
  • Standard <8K Synchronous GRPO / PPO (Tier 3): `verl` 3D-HybridEngine + `CuMemAllocator` delivers 2.1s zero-redundancy resharding on a single colocated pool.

⛔ Not For (When to Avoid)

  • Never abort or drop unfinished long rollouts to save time: Dropping long rollouts teaches the model a catastrophic short-answer length bias.
  • Never run async partial rollouts without Per-Token TIS: Uncorrected multi-step staleness causes KL divergence spikes.
