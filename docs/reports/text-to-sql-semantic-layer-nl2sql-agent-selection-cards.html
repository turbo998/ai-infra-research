Good Fit vs. Not For: Anchor Enterprise ChatBI on a Governed Semantic Layer & LSH Value Index

Actionable architecture rules for enterprise Text-to-SQL and Data Agent platforms.

✅ Good Fit (When to Adopt Tier 4 / Tier 3)

  • Executive BI Copilots & Financial Reporting (Tier 4): Mandatory whenever KPI definitions (`NRR`, `GMV`, `Churn`) must match audited board reports with <1% drift.
  • Large Enterprise Lakehouses With 100–2,000+ Tables (Tier 4): Dual-track semantic DSL + LSH column pruning keeps prompts at ~5.4K tokens and 2.1s latency.
  • Ad-Hoc Data Science Exploration Over Unmodeled Tables (Tier 3): LSH cell-value linking + read-only EXPLAIN loop reaches 78.6% accuracy without upfront YAML modeling.

⛔ Not For (When to Avoid)

  • Full-Schema DDL Stuffing on >20 Tables (Tier 1): Causes severe homonym column confusion (38.5% EX) and burns $289.50 per 1,000 queries.
  • DDL-Only Vector RAG Without Cell-Value Indexing (Tier 2): Blindly guesses WHERE string literals and returns 0 rows on coded columns.
  • Executing Raw LLM SQL Without `SQLGlot` AST Partition & RLS Guards: Risks unauthorized data exposure and expensive full-table scans.

Day-1 Production Text-to-SQL Checklist

1. Define core KPIs and verified join trees in a declarative Semantic Layer (MetricFlow / Cube / Fabric IQ).
2. Index distinct categorical/entity cell values with 3-gram MinHash LSH + Embeddings.
3. Parse all generated SQL with SQLGlot to inject RLS predicates and enforce partition-key filters.
4. Run a read-only EXPLAIN dry-run self-correction loop and display a Metric Lineage Card in the UI.
