When to Adopt Phase 93 Optimizations vs Where Guardrails Are Mandatory

Production deployment matrix for AI Infrastructure Architects across GPU kernels, serving engines, and RLHF training.

✅ Good fit (Adopt Immediately)

  • SM100 Sparse-MLA Training (`requires_grad`): Always enable `o_lo` residual saving + `rescale_threshold=0.0` to eliminate peaked-row gradient blowups (15.83x lower error) at only ~8% forward cost and 1 extra BF16 output-sized tensor.
  • Small-Batch Decode & Sampling: Use FlashInfer `act_and_mul_split_kernel` when `num_tokens < 2 * num_sms` (3.15x HBM bandwidth) and deferred `last_valid_index` reduction (0 normal-path block reductions).
  • Rubin `sm_107a` Long-Context MLA: Enable the shaved 1-wave plan (`MLA2_SHAVE_TILES=48`) for $\ge 1024$ key tiles to harvest the 16 otherwise-idle SMs on 208-SM boards.
  • Multi-Tier KV Offload & Routing: Configure vLLM `sync_load_budget_bytes` (e.g., 8–16 MiB/step) for sub-millisecond inline CPU hits, and deploy Dynamo's 33-byte `OwnerId` edge slots for 3.4x denser KV routing indexes.

⛔ Not for (Enforce Guardrails)

  • Bitwise-Deterministic Rubin Cross-Run Auditing: Rubin's shaved 1-wave plan introduces a 2-partial `merge_w1` reduction that can differ by up to 1 BF16 ULP from equal-length plans; disable when strict single-item bitwise identity is required.
  • Aggregated DSv4.1 with Attention TP > 1: Do NOT default aggregated servers to `flashmla_mega` when `attn_tp_size > 1` (<64 query heads/rank); use `flashmla` instead.
  • Fixed Shared-Memory Radix Top-K Buckets: Never bound candidate staging buffers to `4096` in SMEM; adversarial or tied FP32 scores require `(batch, 2, seq_len)` global workspaces.
  • Non-Blocking FSDP2 CPU Offload on Uneven Shards: Never use `non_blocking=True` D2H in `offload_fsdp2_model_to_cpu` when shards require CPU repadding.
