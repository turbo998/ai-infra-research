✅ 为什么稠密模型 (Dense 405B) 用不了 KTransformers 的神速？
稠密模型每个词要激活全部 405B（220GB）参数，即使在 760 GB/s DDR5 上原位读一遍也要 300ms；而 671B MoE 每个词只激活 37B（其中冷专家仅 ~15GB），760 GB/s DDR5 读一遍仅需 20ms！
✕ 为什么绝对不能把 MLA 注意力或 KV Cache 放 CPU？
MLA 注意力需要跨 16K~128K 历史 Token 做高并发矩阵乘，算力需求远超 CPU 极限；把 MLA 和 KV 锁死在 48GB GPU 显存里才能实现 6.8 秒极速 Prefill！
Matrix Summary: Sparse MoE architecture (`5.5%` active parameters) is uniquely suited for GPU-CPU heterogeneous execution: GPU handles dense attention, while CPU DDR5 handles sparse expert lookup.

// 2. 单层 MoE 异构并发执行：GPU 算共享专家的同时，双路 CPU AMX 在本地 NUMA 内存算 8 个路由专家
void heterogeneous_moe_layer_forward(Tensor d_hidden, ExpertWeightsCPU& cpu_experts) {
  auto [topk_ids, topk_weights] = gpu_router_gate(d_hidden); // 在 GPU 上算出选中的 8 个专家 ID
  cudaMemcpyAsync(h_pinned_act, d_hidden.data(), 14336, cudaMemcpyDeviceToHost, stream_pcie);
  launch_gpu_shared_expert_async(d_hidden, stream_gpu_compute); // GPU 并行算共享专家!

  cudaStreamSynchronize(stream_pcie); // 仅传 14KB，耗时 0.0003ms!
  #pragma omp parallel num_threads(64)
  {
    int socket_id = omp_get_thread_num() / 32; // 严格绑定本地 NUMA 节点内存，零跨 UPI 流量
    amx_gemv_int4_numa_local(h_pinned_out[socket_id], h_pinned_act, cpu_experts, topk_ids, socket_id);
  }
  cudaMemcpyAsync(d_routed_out, h_pinned_out, 14336, cudaMemcpyHostToDevice, stream_pcie);
  fuse_add_shared_and_routed(d_hidden, d_routed_out, stream_gpu_compute);
}
// <answer> Validated: 18.60 tok/s interactive Decode, 0.032 MB PCIe/tok, 6.8s 16K prefill

🔥 什么时候应该从 Tier 4 切换到 Tier 3 (FlexGen)？
计算拐点公式：当并发 `Batch Size > 64` 时，激活矩阵变大而 CPU AMX 算力开始饱和，此时用 Tier 3 (FlexGen Zig-Zag) 把权重搬进 GPU 用强大的 Tensor Core 一次横扫 128 个 Batch 吞吐更高（310 vs 195 tok/s）！
⚠️ 组装 KTransformers 服务器的“第一大坑”
千万别买只插了 2~4 根内存条的工作站！如果双路服务器只插 4 根 DDR5（仅激活 4 个通道，带宽 `150 GB/s`），生成速度会直接从 `18.6 tok/s` 掉回 `4.5 tok/s`！必须插满 16~24 个通道！
Robustness Conclusion: For interactive MoE serving (`Batch 1–8`), Tier 4 (KTransformers in-place CPU compute) wins by 8.86×; for offline bulk jobs (`Batch 128+`), Tier 3 (FlexGen Zig-Zag) wins by 6.46×.

7 / 7 · MY TAKE · GOOD FIT VS NOT FOR & PRODUCTION READINESS Architect Decision Guide

架构师总结：实时跑 671B 选 KTransformers 原位计算，夜间批量跑批选 FlexGen

用“GPU 显存管密集注意力 + 24 通道 DDR5 管稀疏专家”将满血 671B 部署门槛拉进 2 万美元以内。

✅ Good Fit (强烈推荐场景)

  • • 政企部门/研究院低成本私有化跑满血 671B DeepSeek-R1 (1~8 并发交互) → Tier 4 (KTransformers / Fiddler)：$1.85万单机跑出 18.6 tok/s，立省 88% 硬件采购费。
  • • 夜间非实时大批量离线文档处理 (Batch=128) → Tier 3 (FlexGen Zig-Zag)：列优先横扫平摊权重搬运，跑出 310 tok/s 高吞吐。

⛔ Not For (严禁踩坑场景)

  • • 严禁对 671B MoE 使用“按层把专家权重拷进 GPU”的传统卸载 (Tier 2)：每词搬 17GB 权重会把速度死锁在 2.1 tok/s。
  • • 严禁购买只插了 2~4 根内存条的服务器跑 CPU 专家卸载：未插满 16~24 条 DDR5 内存通道会导致带宽暴跌 75%。
  • • 严禁在不绑 NUMA 的情况下跨两颗 CPU 跑专家矩阵乘：跨 UPI 总线会吃掉一半内存带宽。
🛠️ 生产上线 4 步核验清单 (Production Readiness Checklist)

1. [ ] 采购硬件时确保插满双路 CPU 的全部 16~24 条 DDR5-5600/6400 内存通道（实测流带宽 >600 GB/s）。
2. [ ] 开启 BIOS Sub-NUMA Clustering 与 KTransformers NUMA-Striped 专家切分，杜绝跨 Socket 内存读取。
3. [ ] 将 MLA 注意力 + KV Cache + 共享专家 100% 锁定在 48GB GPU 显存内，仅将稀疏路由专家放在 DDR5。
4. [ ] 核验 CPU 支持并启用了 Intel AMX 或 AMD AVX-512 VNNI 硬件矩阵指令集。
