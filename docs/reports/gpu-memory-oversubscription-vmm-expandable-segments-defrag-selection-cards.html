Stitching 2MB Physical Slabs via cuMemMap & Unmapping RL Weights Without Breaking CUDA Graphs
// 1. CUDA Driver VMM: Stitching Scattered 2MB Physical Slabs into Contiguous Virtual Memory
CUdeviceptr dptr;
cuMemAddressReserve(&dptr, 64ULL << 30, 0, 0, 0); // Reserve 64GB virtual address space (0 physical HBM!)

// When tensor or vAttention KV Cache grows by +2MB:
CUmemGenericAllocationHandle slab_handle;
cuMemCreate(&slab_handle, 2ULL << 20, &prop, 0);  // Grab any free 2MB physical slab in HBM
cuMemMap(dptr + current_offset, 2ULL << 20, 0, slab_handle, 0); // Stitch via GPU MMU in 15us!
cuMemSetAccess(dptr + current_offset, 2ULL << 20, &accessDesc, 1);

# 2. PyTorch 1-Line Activation & Colocated RL Graph-Safe Weight Sleep/Wake (verl / SGLang)
export PYTORCH_CUDA_ALLOC_CONF="expandable_segments:True"

# During RL Rollout -> FSDP Training Transition:
def sleep_rollout_weights(vmm_segment):
    # Unmaps physical 2MB HBM pages for FSDP to use, but KEEPS virtual address dptr locked!
    cuMemUnmap(vmm_segment.dptr, vmm_segment.size)
    cuMemRelease(vmm_segment.physical_handle)

def wake_rollout_weights(vmm_segment):
    # Remaps fresh physical pages to the EXACT SAME virtual pointer -> CUDA Graphs stay 100% valid!
    cuMemCreate(&new_handle, vmm_segment.size, &prop, 0)
    cuMemMap(vmm_segment.dptr, vmm_segment.size, 0, new_handle, 0)
Deterministic Verifier: Because vmm_segment.dptr never changes across sleep() and wake(), SGLang/vLLM never has to re-capture CUDA Graphs between RL rollout generations.

✅ Good Fit (When to Use Tier 3 / Tier 4)
