Architectural Stability Rule

Notice the crossover: for standard chat alignment (P99 ≤ 2K–4K), Tier 3 Synchronous HybridEngine gives 90% of the benefit with zero off-policy complexity. Once you train reasoning models (P99 ≥ 16K–64K), synchronous barriers waste over half of cluster FLOPs, making Tier 4 Partial Rollout mandatory.

Robustness Takeaway: Always match the rollout scheduler to your P99/P50 length skew ratio rather than copying a static RLHF config across short-chat and long-CoT workloads.

7 / 7 · MY TAKE GOOD FIT VS. NOT FOR & READINESS

Architect Playbook: When to Standardize on Synchronous HybridEngine vs. Asynchronous Partial Rollout

Clear presales & production boundaries for enterprise RLHF, GRPO reasoning, and multi-turn Agentic RL clusters.

✅ Good Fit

• Tier 3 HybridEngine (verl) for all short/medium CoT (≤ 4K–8K tokens) instruction alignment and DPO/PPO/GRPO runs needing 100% strict on-policy convergence.
• Tier 4 Async Partial Rollout (AReaL / StreamRL / Kimi k1.5) for DeepSeek-R1-style Long-CoT (16K–64K tokens) and multi-turn tool-use Agentic RL where P99/P50 length skew exceeds 3.0x.
• Tier 2 Static Ray Split (OpenRLHF) for rapid 16–64 GPU prototyping with isolated container sandboxes.

⛔ Not For

• Never use Tier 1 Naive FSDP/ZeRO-3 .generate() on 13B–70B+ models (wastes 88.5% of GPU FLOPs on per-token All-Gather).
• Do not run Co-Located HybridEngine without cuMemUnmap Sleep Mode and CPU Adam offload (causes immediate HBM OOM between vLLM KV blocks and backward activations).
• Do not run unbounded asynchronous RL (τ ≥ 5) without Dual-Clip truncated importance sampling.

6-Point Production Readiness Checklist

1. [x] Reshard Actor weights into vLLM / SGLang (TP=2/4/8) with PagedAttention for every rollout phase.
2. [x] Enable vLLM Sleep Mode (cuMemUnmap) to unmap KV Cache physical HBM pages before backward passes.
3. [x] Fuse on-the-fly BF16 → FP8 (E4M3) weight casting into the 3.2 s CUDA IPC resharding step.
4. [x] Enable Partial Rollout KV prefix continuation whenever P99 / P50 trajectory length > 3.0x.
5. [x] Enforce max_staleness_steps ≤ 2 and Dual-Clip truncated importance sampling in async streaming RL.
6. [x] Offload CPU-heavy code execution and math verification sandboxes to an elastic asynchronous CPU pool.
