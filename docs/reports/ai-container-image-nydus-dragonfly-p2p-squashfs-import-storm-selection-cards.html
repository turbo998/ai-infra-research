4 / 7 · UNDER THE HOOD NYDUS EROFS & SQUASHFS LOOPBACK

底层内幕：为什么 `import torch` 会产生 7,373 万次元数据风暴？如何归零？

# 1. Python import 风暴账本 (4,096 Ranks 共享 Lustre/NFS 上的散装 conda 目录): # 每个 Python 进程执行 import torch, transformers 时，会沿着 sys.path 的 15 个目录 # 逐个执行 stat() / open() 查找约 1,200 个 .py / .so 模块 -> 单进程约 18,000 次元数据 RPC! # 4,096 Ranks * 18,000 = 73,728,000 次 MDS 请求瞬间打死共享存储元数据服务器 (耗时 185s)!
↓ SquashFS 单文件封装 + Nydus EROFS 内核态挂载指令 (`<answer>`) ↓
# 2. 将 15 万个散装小文件打包成单个只读 SquashFS 镜像 (zstd 压缩 + 4K 对齐): mksquashfs /path/to/conda/env /shared/envs/llm_env.sqsh -comp zstd -Xcompression-level 6 -noappend # 3. 各节点启动时用 Loopback 挂载 (或拷贝至 /dev/shm 内存盘)，MDS 仅需打开 1 个文件! mount -t squashfs -o loop,ro /shared/envs/llm_env.sqsh /opt/conda/envs/llm
