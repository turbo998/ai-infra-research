Threshold Gating Summary / 阈值门控结论

• TE dynamic SMEM opt-in threshold is exact at `num_tensors == 2048` (`(3*2048+1)*8 = 49,160 B > 49,152 B`).
• Mooncake advances GID iff `attempt.endpoint_id > state.first_failed_endpoint_id > 0` on matching `selection_epoch`.

Failure Analysis (`✕` Markers) / 缺陷根因分析

• Clamping negative top-$k$ KL (`Q_k > P_k`) zeroes out student gradients on overconfident tokens.
• Freeing RDMA notify buffers after `deconstructLocked()` failure or unknown CQE risks silent RNIC DMA corruption.

Why One-Sided Epsilon in `compute_tail_bucket_kl`?

When teacher tail $1 - P_k = 0$ ($P_k = 1.0$), $x \log x \to 0$ by continuity, so `compute_tail_bucket_kl(0.85, 1.0, 1e-6)` evaluates to exact `0.0`. Clamping $1 - P_k$ to `1e-6` would inject artificial bias on deterministic teachers!

Why Exclude Triton from `_refittable_mxfp4_backends`?

FlashInfer CUTLASS, DeepGEMM, and Marlin publish converted weights via `replace_parameter`, which `_replace_parameter_in_place` intercepts. Triton stores non-Parameter wrappers on the quant method, bypassing in-place refit.

7 / 7 · MY TAKE · ARCHITECT GUIDANCE & PRODUCTION READINESS PRODUCTION DECISION MATRIX

架构师总结：何时启用 TE Grouped MXFP8 仿真、Mooncake 有界重分片与 veRL 尾桶蒸馏

Actionable deployment boundaries for solution architects building Blackwell SM100 training/inference clusters and RoCEv2 RL post-training pipelines.

✅ Good Fit / 推荐启用场景
  • Blackwell SM100 Hopper-Recipe Migration: Use `nvte_swizzle_grouped_block_scaling_to_mxfp8_scaling_factors` to run 1D/2D FP8 block-scaled MoE models inside CUDA Graphs without copying FP8 data (`1.2944x` scale upper-bound slack for 256 experts).
  • Multi-Subnet / Containerized RoCEv2 Fabrics: Enable Mooncake `PeerAutoGidStateTable` (`kNetworkPrivateV4` tier + 2-endpoint failure confirmation) to auto-heal across `10/8` private IPv4 and overlay GIDs without manual `NCCL_IB_GID_INDEX` tuning.
  • RL Weight Resharding on 400GbE: Configure `max_inflight_batches = 4` in `MooncakeTransferEngineExecutor` to achieve `357.85 Gbps` (`+14.3%` over sync) with a bounded `1 GiB` window.
  • Low-Precision RL Rollout + Top-K OPD: Pair veRL `MXFP4` (`flashinfer_cutlass` `MXFP4×MXFP8`, `6.25%` refit staging) with `loss_mode=forward_kl_topk_tail` (`tail_mass_eps=1e-6`).
⛔ Not For / 严禁混用或误用场景
  • Simultaneously Varying First & Last Dims: Do not pass grouped tensors where both `first_dims` and `last_dims` vary on device (`NVTE_CHECK` rejects unbounded 2D product padding).
  • >9,685 Grouped Tensors on SM100: Exceeds Blackwell's `227 KiB` opt-in dynamic shared memory limit (`(3n+1)*8 > 232,448 B`).
  • Reusing Poisoned RDMA Submissions: Never ignore `TransferCompletionUnknownError` or free `notify_` buffers when `deconstructLocked()` fails; RNIC DMA may still write to host pages.
  • Combining `forward_kl_topk_tail` with `use_policy_gradient=true`: Policy gradient updates only the single sampled token $y_t$ and corrupts alignment when non-sampled top-$k$ tokens diverge.
  • Triton MXFP4 Backend or TRTLLM Qwen3.5 MXFP4×MXFP8: Triton lacks `Parameter`-level in-place refit; TRTLLM `MXFP4×MXFP8` is numerically inaccurate on Qwen3.5 in vLLM 0.29.
