Perturbation & Consistency Analysis

1. 为什么 512 个活跃适配器下 Tier 3 (`340ms`) 突破了 250ms SLA，而 Tier 4 仅 `118ms`？ 因为 Tier 3 的固定槽位（如预留 32 个最大 Rank 槽位）在 512 个异构 Rank 模型轮番请求时发生高频同步驱逐；而 Tier 4 利用统一分页池按实际 Rank 动态分配页，并在前一层 Attention 期间异步预取下一批权重页。

2. 精度一致性：数学上 $X W_0 + (X A) B$ 与合并权重 $X(W_0 + BA)$ 仅存在微小的浮点结合律舍入差异（`< 1e-4`），下游任务精度 100.0% 等价。

Robustness Conclusion: Unified KV+LoRA paging (`S-LoRA`) eliminates the memory boundary between context length and adapter count, scaling smoothly to 500+ concurrent adapters.

7 / 7 · MY TAKE Architect Playbook & Readiness

架构师决断：何时用 vLLM Multi-LoRA，何时上 S-LoRA 统一分页池，如何砍掉 96.9% 显卡账单？

给企业 AI 中台与多租户模型服务团队的落地指南。

✅ Good fit (强烈推荐)

  • 32～1,000+ 个异构 Rank 垂类模型混部 → 选 Tier 4 (S-LoRA 统一分页池 + MBGMM)：4 张卡替代 128 张卡，月省 $226,300 (-96.9%)，512 并发适配器下 P99 TTFT 仅 118ms。
  • ≤32 个同秩微调模型快速上线 → 选 Tier 3 (vLLM `--enable-lora`)。
  • 网关开启 LoRA-ID 一致性哈希亲和路由：最大化显存适配器命中率。

⛔ Not for (严禁踩坑)

  • 严禁对多部门微调模型执行 `merge_and_unload()` 导出全量 70GB 模型独立部署：浪费 32 倍显卡与显存。
  • 严禁在单实例上用串行锁切换 LoRA：打碎 Continuous Batching 导致延迟超标 7 倍。
  • 严禁将未缓存的冷门 LoRA 放在慢速网络盘按需读取：必须预加载进 Host Pinned DRAM (`--max-cpu-loras`)。
