✅ 为什么 Prefix Cache 让 Contextual 建库便宜 90%？
同一篇文档的 20 个切片共享完全相同的全文前缀（Document Prefix）。开启 vLLM/SGLang Prefix Caching 后，整篇文档只需算 1 次 Prefill，生成 20 个切片背景头每 10M Token 仅需约 $24！
✕ 为什么纯向量检索做不了“全库 Top-5 风险汇总”？
向量检索的本质是“局部语义相似度匹配（Top-K Similarity）”，它没有全局计数器和跨文档聚合能力，必须靠概念子图或结构化元数据过滤。
Matrix Summary: Tier 3 solves local & pronoun-heavy retrieval (`94.6% / 91.8%`); Tier 4 solves global & multi-hop synthesis (`88.5%`) without Eager GraphRAG's `$4,850` indexing bill.

def answer_enterprise_query(query: str) -> str:
    intent = classify_query_intent(query)  # <15ms classifier: "LOCAL_FACTOID" vs "GLOBAL_MULTIHOP"
    if intent == "LOCAL_FACTOID":
        cands = rrf_merge(bm25.search(query, k=50), dense.search(query, k=50))
        top5 = cross_encoder.rerank(query, cands, top_k=5)  # Each chunk carries Contextual Header!
        return llm.generate(query, context=top5)

    # GLOBAL_MULTIHOP: LazyGraphRAG iterative best-first concept subgraph expansion
    seed_concepts = concept_index.match_noun_phrases(query, top_k=12)
    subcommunities = leiden_graph.best_first_expand(seed_concepts, budget_chunks=30)
    claims = parallel_extract_atomic_claims(query, subcommunities.chunks)
    return llm.synthesize_global_report(query, claims)

7 / 7 · MY TAKE · GOOD FIT VS NOT FOR & PRODUCTION READINESS Architect Decision Guide

架构师总结：用 Contextual Header 消灭孤儿切片，用 LazyGraphRAG 替代天价全量图谱

坚持“意图路由分流：80% 单跳走 Contextual Hybrid (245ms) + 20% 多跳走 LazyGraphRAG (680ms)”的企业知识中台标准架构。

✅ Good Fit (强烈推荐场景)

  • • 跨文档审计归纳、研报产业链穿透、复杂法务合规 → Tier 4 (自适应路由 + LazyGraphRAG)：建库仅 $38/10M Tok，全局多跳准确率从 38.5% 跃升至 88.5%。
  • • 政企规章制度、技术手册、合同条款精准问答 → Tier 3 (Contextual / Late-Chunking + BM25 + Reranker)：245ms 拿到 94.6% 单跳与 91.8% 跨段指代准确率。

⛔ Not For (严禁踩坑场景)

  • • 严禁在长篇财报/合同库裸跑无背景头的 512-Token 硬切片 (Tier 1)：代词丢失主语导致跨段召回率腰斩至 54.0%。
  • • 严禁在日更百万 Token 级动态知识库上跑初代 Eager Full GraphRAG：$4,850/10M Tok 的离线 LLM 抽图账单与社区重算会让项目直接停摆。
  • • 严禁不加意图路由把所有简单查询都送进 GraphRAG：查单个参数跑图遍历纯属浪费 400ms+ 延迟。
