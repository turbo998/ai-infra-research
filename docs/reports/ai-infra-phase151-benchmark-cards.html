7 / 7 · MY TAKEGOOD FIT VS NOT FOR & READINESS

Architectural Guidance: Where Phase 151 Patterns Deliver Immediate Production Value

Synthesizing deployment recommendations for solution architects across GPU kernels, LLM serving engines, and distributed KV fabrics.

✅ Good Fit

  • CudaGraph Chunked LM-Head + Loss: Passing caller valid_rows and step_peak_budget avoids wasted GEMM on padded rows and bounds backward memory.
  • Large-Batch ROCm W4A16 & Muse Spark MoE: Using 64-bit row offsets prevents 2 GiB index wraparound; dedicated CUDA routing cuts dispatch latency 3.82x.
  • Disaggregated EPD & KV Routing: Sending metadata-only media descriptors to prefill workers and building KV router candidate rows outside the queue actor lock.
  • RDMA / io_uring KV Transfers: Enforcing strict cqe->res == len checks in Mooncake TENT and locking Libfabric endpoints across progress threads.

⛔ Not For

  • Unbounded Fine-Grained KDA Binning on Tiny Prefills: When sequence count/length is short, per-task bin construction overhead exceeds the kernel gain; use plain N32 work bins instead.
  • FP32 MoE Combine in Batch-Invariant RL Rollouts: FP32 combine accumulation drifts from training; require FP64 accumulation for bitwise-consistent policy verification.
  • Unlocked Libfabric Progress Threads: Allowing background completion polling without ep_mutex_ corrupts AV/CQ state on multi-rail EFA/CXI fabrics.
