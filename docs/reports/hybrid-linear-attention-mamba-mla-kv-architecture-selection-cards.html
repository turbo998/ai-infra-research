✅ 为什么 MLA 要单独拆出 64 维“解耦 RoPE ($k_t^R$)”？
旋转位置编码（RoPE）矩阵随相对位置动态变化，若直接加在压缩潜变量上会导致 $W^{UK}$ 无法被静态吸收进 Query！将 64 维位置向量解耦出来单独拼接，才实现了完美的免解压矩阵吸收！
✕ 为什么固定 4K 滑动窗口 (SWA) 救不了长文档问答？
一旦跨度超过窗口阈值，早期 Token 的精确键值被滑出窗口丢弃，只靠深层隐式传递无法还原精确数字与专有名词。

# 1. DeepSeek MLA Decode 矩阵吸收：全程不解压 K 和 V，HBM 仅读取 576 维压缩潜变量！
def mla_decode_absorbed(q_nope, q_pe, c_kv_cache, k_pe_cache, W_UK, W_UV, W_O):
    q_absorbed = torch.einsum("bhd,hdc->bhc", q_nope, W_UK)        # 将 W_UK 提前吸收进单 Token Query!
    scores = (q_absorbed @ c_kv_cache.T) + (q_pe @ k_pe_cache.T)   # 直接与 512 维潜变量做内积
    attn_probs = torch.softmax(scores * scale, dim=-1)
    latent_out = attn_probs @ c_kv_cache                           # [B, H, 512] 潜空间聚合
    return torch.einsum("bhc,hcd->bhd", latent_out, W_UV) @ W_O    # W_UV 吸收进输出投影

# 2. SGLang MambaRadixCache (#46168)：恢复混合模型的 16 层 Paged KV + 48 层 SSM 递归状态快照
def match_hybrid_prefix(radix_tree, token_ids):
    node, matched_len = radix_tree.find_longest_chunk_aligned_prefix(token_ids, chunk_size=256)
    kv_page_indices = node.full_attn_kv_pages          # 16 层全注意力直接映射分页页表
    ssm_state_clone = node.mamba_recurrent_state.clone() # 48 层 Mamba 克隆第 matched_len 处的快照 h_t!
    return kv_page_indices, ssm_state_clone, token_ids[matched_len:]

✅ Good Fit (强烈推荐场景)

  • • 金融/法务高精度长文多跳推理 + 高并发生成 → Tier 3 (DeepSeek MLA)：KV 显存省 5.69x（5.62GB），大海捞针 97.8% 零遗忘。

⛔ Not For (严禁踩坑场景)

  • • 严禁将纯 Mamba-2 / 纯线性注意力模型 (Tier 2) 用于合同审查或精确取数 RAG：41.5% 的长文捞针率会导致严重幻觉。
