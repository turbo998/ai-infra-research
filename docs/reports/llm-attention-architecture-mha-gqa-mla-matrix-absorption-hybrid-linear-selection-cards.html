2 / 7 · SCENARIO: HOW MATRIX ABSORPTION MAKES MLA DECODE FLY

Why Absorbing `W_UK` into `W_Q` Raises Decode Arithmetic Intensity from 16 to 256 FLOPs/B

If MLA decompressed `c_KV` into 128 K/V heads during Decode, HBM bandwidth would explode. Instead, associative matrix multiplication absorbs `W_UK` into Query projection `W_Q` and `W_UV` into Output projection `W_O`!

  • choice (Weight Matrix Absorption in Decode): Act automatically — Keep `c_KV` (`512`) compressed in HBM; let all `128` Query heads attend to the single shared latent vector (`MQA`-style!).
  • choice (`FlashMLA` TensorCore Kernel): Act automatically — Exploit `AI = 256 FLOPs/Byte` (128 Query heads sharing 1 latent KV) to drive `66.8%` TensorCore utilization during Decode.
  • score (Decoupled RoPE `d_r = 64`): Act automatically — Separate position-sensitive RoPE key (`64`) from latent `c_KV` (`512`) so matrix absorption remains commutative.

Exact Per-Token KV Footprint & Matrix Absorption Math

# 1. Per-Token KV Cache Bytes (FP8 = 1 Byte)
KV_MHA = 2 * L * n_h * d_h # 2*80*64*128 = 1,310,720 B
KV_GQA8 = 2 * L * n_kv * d_h # 2*80*8*128 = 163,840 B
KV_MLA = L * (d_c + d_r) # 61*(512+64) = 35,136 B!

# 2. MLA Decode Weight Absorption Identity
q_t * K_t^T = (x_t * W_Q) * (c_KV * W_UK)^T = x_t * (W_Q * W_UK^T) * c_KV^T
`(W_Q * W_UK^T)` is pre-multiplied or fused so `c_KV` is read only once from HBM!
