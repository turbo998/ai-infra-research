Stage-Before-Admit Async DMA & In-Place Slot Reuse

// When waiting request req needs cold LoRA #42 (not in GPU slots 0..7): if lora_id not in active_gpu_slots: slot = evict_zero_ref_lru_gpu_slot() with torch.cuda.stream(lora_h2d_stream): gpu_lora_B[slot].copy_(pinned_cpu_lora_B[lora_id], non_blocking=True) gpu_lora_A[slot].copy_(pinned_cpu_lora_A[lora_id], non_blocking=True) lora_ready_evt[slot].record(lora_h2d_stream) req.state = STAGING_LORA # Do NOT block current decode step!
↓ Zero-Stall Admission on Next Step (<answer>)
// On subsequent scheduler tick: if req.state == STAGING_LORA and lora_ready_evt[slot].query(): admit_to_running_batch(req, gpu_slot=slot) // 0.08 ms overhead!
In-place `.copy_()` into pre-allocated `gpu_lora_A/B[slot]` keeps `CUDAGraph` valid!

7 / 7 · MY TAKE

Good Fit vs Not For & Production Readiness

✅ Good fit
• Multi-tenant SaaS serving 50–1,000 LoRA adapters per GPU replica
• High-rank (`r = 32..128`) all-linear LoRA deployments (`vLLM`, `S-LoRA`, `SGLang`)
• Latency-sensitive streaming endpoints requiring strict P99 TPOT SLAs
⛔ Not for
• Copying cold LoRA weights onto GPU on the default/compute stream
• Admitting more distinct LoRA IDs into a running batch than `max_loras`
CSP self-contained · Zero external assets · Ready for main branch archive.
