# 1. OSDI VTC Virtual Token Counter with Wake-Up Lift & Asymmetric Prefill/Decode Weights
class HierarchicalVTCScheduler:
    W_CACHE, W_PREFILL, W_DECODE = 0.05, 1.0, 2.5

    def on_tenant_wakeup(self, tenant_id: str, active_tenants: list[str]) -> None:
        # Prevent idle credit hoarding: lift waking tenant to current active minimum!
        min_active_v = min((self.v[t] for t in active_tenants), default=0.0)
        self.v[tenant_id] = max(self.v[tenant_id], min_active_v)

    def charge_step(self, tenant_id: str, cached_tok: int, in_tok: int, out_tok: int) -> None:
        cost = self.W_CACHE * cached_tok + self.W_PREFILL * in_tok + self.W_DECODE * out_tok
        self.v[tenant_id] += cost / self.tenant_weight[tenant_id]

7 / 7MY TAKE · GOOD FIT VS NOT FOR & PRODUCTION READINESS
Architect Verdict: Standardize on Weighted VTC + Wake-Up Lifting + Work-Conserving Spot Borrow

✅ Good Fit (When to Use Tier 4)

  • Enterprise Shared AI Platforms: Mixes real-time chat/coding assistants with heavy 64K RAG and nightly evaluation jobs on the same GPU pool.
  • Internal Chargeback & FinOps: Asymmetric token weights (`0.05 / 1.0 / 2.5`) provide an exact, dispute-free GPU cost ledger per department.
  • Tiered SaaS Offerings: Monetizes idle capacity via discounted `Spot Borrow` API tiers.

⛔ Not For (When to Avoid)

  • Never use request-count (RPM) limits alone for LLMs (Tier 2): Always rate-limit and schedule on weighted ITPM + OTPM.
  • Never omit wake-up counter lifting in VTC: Unlifted counters allow bursty tenants to starve steady interactive tenants.
