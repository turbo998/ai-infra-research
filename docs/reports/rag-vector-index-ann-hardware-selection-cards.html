Perturbation & Consistency Analysis

1. 为什么 1,000 万（10M）规模下直接选 Tier 2 即可？ 10M 向量在 Tier 2 下仅占 23.6 GB DRAM，单台常规服务器即可全内存承载，兼得 3.10 ms P99 与 $182/mo 低成本。

2. 十亿级冷热分层（Hot/Warm Tiering）最佳实践：将最近 7 天高频访问的热点分片（10%）放在 Tier 2/Tier 4，将 90% 的历史归档分片放在 Tier 3 (`NVMe DiskANN`)。

Robustness Conclusion: `50M–100M vectors` is the economic inflection point where `NVMe DiskANN` saves over `$60,000/year` per shard compared to uncompressed DRAM HNSW.

架构师决断：何时用 SQ8/RaBitQ 内存量化，何时用 NVMe DiskANN，何时上 GPU cuVS CAGRA？

给企业知识库架构师与 RAG 平台负责人的生产落地指南。

✅ Good fit (强烈推荐)

  • 1,000 万～1 亿条低延迟热库 (≤5ms) → 选 Tier 2 (SQ8 / RaBitQ + Top-100 精排)：内存立省 71.9%，P99 达 3.10 ms。
  • 1 亿～100 亿条企业全量知识库归档 → 选 Tier 3 (NVMe SSD DiskANN Vamana)：DRAM 缩减 18.56x 至 48 GB/亿条，月租立省 91.0%。
  • 日更亿级建库与万级 QPS DeepResearch Agent 风暴 → 选 Tier 4 (GPU cuVS CAGRA)：55 分钟极速建库，22,400 QPS。

⛔ Not for (严禁踩坑)

  • 严禁在 ≥5,000 万规模生产库保留未压缩 FP32 HNSW：891GB/亿条的纯 DRAM 账单会迅速失控。
  • 严禁将普通 HNSW 直接 `mmap` 到 SSD 或在云端 EBS 网络盘上跑 DiskANN：必须绑定本地直连 NVMe 与 4KB 耦合布局。
  • 严禁对带租户/时间过滤的查询使用 Post-Filtering：必须开启内联 Roaring Bitmap 边过滤。
