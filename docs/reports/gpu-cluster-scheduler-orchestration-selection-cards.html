Perturbation & Scaling Analysis

1. 为什么 16 卡时 Tier 3 (`79.5%`) 能赢 Tier 2 Slurm (`78.0%`)，到 128 卡却反输 `8.5` 个百分点？ 因为 16 卡仅需 2 台节点，跨 Spine 冲突小，统一池化消除了 Slurm 的 14% 孤岛；但到了 128 卡，无拓扑感知的 Tier 3 把节点撒满 8 个机柜，跨 Spine 拥塞吃掉了统一池化的红利。

2. Tier 4 如何同时击败 Tier 2 与 Tier 3？ 既用 `Kueue TAS` 复刻了 Slurm `topology/tree` 的整柜紧致分配，又保留了 K8s 训推潮汐借用，在 256 卡下领先 Tier 3 达 **`+28.3` 个百分点**！

Robustness Conclusion: Any cluster running multi-node jobs `≥ 32 GPUs` must enforce switch-level topology packing (`Kueue TAS` or `Slurm topology/tree`).

7 / 7 · MY TAKE Architect Playbook & Readiness

架构师决断：何时用 Slurm，何时用 Kueue TAS + K8s DRA，如何消灭集群死锁与跨脊降速？

面向智算中心架构师与平台工程团队的落地指南。

✅ Good fit (强烈推荐)

  • 企业训推一体 AI 平台 / 多租户智算云 → 选 Tier 4 (K8s + Kueue TAS + K8s DRA + TopologyManager)：单柜紧致装箱 + 机内 PIX 对齐 + 夜间潮汐借用，Goodput 达 88.6%，512 卡月省 $377.5k。
  • 100% 纯离线预训练科研集群 → 选 Tier 2 (Slurm + Pyxis + topology/tree) 或在 K8s 上通过 Slinky / SUNK 托管虚拟 Slurm 队列。
  • 单机/双机小规模任务池 → 选 Tier 3 (Kueue / Volcano Gang) 快速消除互锁死锁。

⛔ Not for (严禁踩坑)

  • 严禁使用原生 `kube-scheduler` 直接调度多节点分布式训练：18.5% 死锁与 +38% 通信惩罚会吞噬过半算力。
  • 严禁将大型集群永久硬切为无法互通的静态 Slurm 池与 K8s 池：导致夜间闲置推理卡无法被训练任务借用。
  • 严禁在多网卡 GPU 节点上关闭 Kubelet `single-numa-node` 亲和校验：会导致 GPUDirect RDMA 退化为跨 CPU Socket 绕行。
