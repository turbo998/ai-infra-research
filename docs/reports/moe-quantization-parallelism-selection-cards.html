Why Fine-Grained Block Scaling (`1×128` FP8 & `1×16` NVFP4) Prevents Accuracy Collapse

In legacy per-tensor quantization, a single activation outlier spike (`100×` normal magnitude) forces the global scale factor up, squashing 99% of normal weights to zero. By confining each scale factor to 128 elements (FP8) or 16 elements (NVFP4/MXFP4)—and keeping Router Gate + KV Cache in higher precision—outlier blast radius is mathematically isolated to a single micro-tile.

Robustness Rule: Always keep the MoE Router Gate in FP32/BF16 and KV Cache in FP8 even when expert FFN weights use NVFP4/MXFP4.

7 / 7 · MY TAKE ARCHITECT PLAYBOOK & READINESS

Architect Verdict: FP8 + DP/EP + EPLB is the Universal Hopper Default; Reserve NVFP4/MXFP4 for Blackwell & CDNA4

Use this field-ready decision boundary when advising enterprise customers on large MoE / dense model quantization and multi-node parallelism.

✅ GOOD FIT (WHEN TO DEPLOY)

• FP8 Block-Scaled (`1×128` / `128×128`) + DP8/EP8 + DeepEP + EPLB: Default production choice on Hopper (`H100`/`H200`/`H20`) and MI300X/MI325X for DeepSeek-V3/R1, Qwen3-MoE, and Llama-3.1-405B (`99.6%` accuracy, `2.65×` goodput, `-62.0%` TCO).

• NVFP4 / MXFP4 + DP16/EP16 + DeepEP + EPLB: Best TCO choice on NVIDIA Blackwell (`B200`/`GB200`, `SM100`: `NVFP4` 16-elem `E4M3` scale & `MXFP4`) and AMD Instinct `MI350X`/`MI355X` (CDNA 4 `gfx950`: OCP `MXFP4` 32-elem `UE8M0` scale; does NOT run NVIDIA proprietary `NVFP4`) (`1.64×` over FP8, `$0.21/1M`).

• W4A16 (AWQ/GPTQ) + Pure TP (4–8 GPUs): Edge or single-box appliances with low concurrency (`Batch < 16`) where fitting weights on fewer cards is the sole objective.

⛔ NOT FOR (ANTI-PATTERNS TO AVOID)

• Never run NVFP4/MXFP4 on Hopper (`H100`/`H200`), AMD CDNA 3 (`MI300X`/`MI325X`), or Ampere (`A100`): Both Hopper (`SM90`) and CDNA 3 (`MI300X`/`MI325X`) support native `FP8` only and lack native 4-bit `FP4` Tensor/Matrix Cores.

• Never use `Pure TP=16` across nodes for sparse MoE (`≥ 64` experts): Ultra-thin expert slices (`width = 128`) starve Tensor Cores and block on cross-node `AllReduce` twice per layer.

• Never run `W4A16` for high-QPS API pools (`Batch ≥ 32`): Register-level dequantization creates a severe SM instruction bottleneck.

• Never run `EP ≥ 8` without `EPLB` and RDMA: Skewed prompts (`Zipf s=1.15`) cause `+58.9%` P99 TPOT tail spikes on hot GPUs.

5-Point Production Sign-Off Checklist

[✓] 1. Verify GPU SM ISA (`SM90` → FP8 Block-Scaled; `SM100/gfx950` → NVFP4/MXFP4)
[✓] 2. Enforce Mixed-Precision Guardrails (Router Gate in FP32/BF16, KV Cache in FP8)
[✓] 3. Switch Multi-Node MoE (≥16 GPUs) from Pure TP to Attention DP + MoE EP + DeepEP
[✓] 4. Enable EPLB Redundant Hot-Expert Replication (`--enable-eplb`) in Production
[✓] 5. Run Domain Calibration Set (128–512 prompts) Before Promoting FP4 to Tier-1 Math/Medical
