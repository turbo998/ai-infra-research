阈值门控机制 (Threshold Gating)

为什么 `NS5` 在第 5 步停止而非第 6 步？

实验显示第 5 步与单位奇异值的 RMS 偏差为 `0.16767`（均值 `0.93418`），而第 6 步因五次多项式不动点振荡导致 RMS 偏差轻微回升至 `0.22550`（均值 `0.84844`），验证了上游默认 `steps=5` 的最优性。

为什么 `fixed_overhead_num_blocks = 5` 不可省略？

若忽略每个 Split 的 Partial LSE 写回与 Combine 归约固定成本，规划器会将尾部短请求切得过碎，导致 Combine 阶段带宽开销反噬算力收益。

MY TAKE · GOOD FIT VS NOT FOR & READINESS 7 / 7

架构师选型决断：何时在生产集群落地 FlashMLA `V41_FP4`、分布式 Muon 与 Dynamo KV 路由器？

综合算术强度边界、分布式通信拓扑与多轮 Agent 流量特征，给出明确的适用场景与禁区清单。

✅ Good fit（强烈推荐落地场景）

  • 长上下文 MLA 模型 Decode 服务 (`DeepSeek-V3/R1/V4`)：使用矩阵吸收 + `V41` FP8 (`528 B/tok`) 或 `V41_FP4` (`288 B/tok`) 将 Decode 推入 Tensor Core 算力受限区（`496–910 FLOP/B`），并必开 `get_mla_metadata` 消除变长批次尾波失衡（6.0x 加速）。
  • 大规模预训练与 MoE 持续预训练 (`Muon 2D FSDP×TP`)：对内部 2D 线性层采用 `Muon` 5 步五次 Newton-Schulz + `0.2*sqrt(max(A,B))` 宽度缩放，节省 68.54% 优化器状态显存并减少约 26% 收敛所需 Token 数。
  • 共享长前缀的多轮 Agent / RAG 推理集群 (`Dynamo Router`)：开启 `overlap_score_credit_decay = 0.65` 与 `IslBoundingPolicy` (`eff_isl < 2048 & ratio < 0.7`)，在保持 75.26% 命中率的同时旁路 42.0% 远程 NIXL 传输，将 P99 TTFT 压至 163.24 ms。

⛔ Not for（明确不适用或需规避禁区）

  • 在 Decode 阶段显式反压缩 MLA KV Cache：未吸收形态会使每 Token 流量暴涨至 `81,920 B`（算术强度跌回 `1.0 FLOP/B`），吞吐比 GQA-8 还慢 `16x`。
  • 对词嵌入 (`embed_tokens`)、输出头 (`lm_head`) 或 1D 归一化层使用 Muon：非内部 2D 层必须保留 `AdamW`，且严禁在未分片 Owner-Rank 的情况下全卡重复运行 NS5（会导致 `22.48s` 优化器步灾难）。
  • 在突发 Agent 流量下使用无负载衰减的静态前缀哈希 (`Sticky No-Decay`)：热点前缀并发微突发会直接击穿单节点 Prefill 队列，引发 `2.76s+` 的 P99 TTFT 雪崩。
  • 当 Decode 节点高负载时强行旁路远程 Prefill：必须由 `DecodeLoadGate` 守卫，否则本地增量 Prefill 会抢占 Decode 迭代并破坏 TPOT SLA。
