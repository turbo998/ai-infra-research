How Hybrid `VisionZip + FastV` Prevents Multi-Turn Visual Amnesia

If pruning relies *solely* on Turn 1's text query (`Naive FastV`), unqueried text blocks in other corners may be dropped (`-10.4 pts` on Turn 2). By combining **Visual Dominant Key Norm (which automatically preserves all high-contrast ink/text/icon patches across the whole page)** with **Contextual Token Merging (`VisionZip`)**, Tier 4 discards only true blank margins/backgrounds—retaining 88.8% multi-turn accuracy 🏆!

Robustness Conclusion: Use Tier 3 (2,304 tokens) for ultra-dense all-text pages, and Tier 4 (720 tokens with VisionZip ink preservation) for general documents, charts, UI screens, and video.

7 / 7 MY TAKE · ARCHITECT DECISION GUIDANCE & PRODUCTION READINESS

Good Fit vs. Not For: Standardize on NaViT 2×2 Pixel-Shuffle + Layer-2 Pruning

Actionable rules for AI Solution Architects deploying production Vision-Language Models.

✅ Good Fit (When to Adopt Tier 4 / Tier 3)

  • High-Res GUI Agents, Charts & Multi-Page Docs (Tier 4): Compresses 2K images to 720 tokens for 195ms TTFT and 90.1% accuracy.
  • Multi-Frame Video & Screen Recording Understanding (Tier 4): Fits 16–64 high-res frames comfortably inside standard HBM budgets.
  • Multi-Turn Arbitrary-Corner Inspection of 1 Blueprint (Tier 3): Keep all 2,304 `2×2 Pixel-Shuffle` tokens when every square millimeter may be queried across 10 turns.

⛔ Not For (When to Avoid)

  • Fixed 336×336 Thumbnail Models on Text/UI (Tier 1): Destroys small text legibility (44.5% accuracy).
  • Unmerged 1-to-1 ViT Patch Feeding on High-Res Images (Tier 2): 9,216 tokens/image wastes $232/10k queries.
  • Unbounded `max_pixels` in Production APIs: Always cap `max_pixels` to prevent 8K images from causing OOM.

Day-1 Production High-Res VLM Checklist

1. Use a native dynamic resolution encoder (NaViT + 2D-RoPE) with 2×2 Pixel-Shuffle projection.
2. Configure explicit min_pixels and max_pixels guardrails at the API gateway.
3. Enable Layer-2 hybrid dominant + cross-modal token pruning (VisionZip + FastV) for multi-image/video workloads.
4. Enable temporal patch deduplication across consecutive screen/video frames.
