## 一、中文深度研究摘要 (Chinese Executive Summary)

### 1. Track A：FlashInfer Blackwell/Hopper 算子栈（`flashinfer-megamoe-topk-sm103-ag-svdquant-kda-weakref-mxfp4-k128`）
- **Cake KDA Weakref Checkpointing 与 `zero_init=False`（`4f88101e60`, PR `#7069`）**：
  - 将 `ChunkKDAFunction` 在 autograd `ctx` 上对 `workspace` 的强引用改为 `weakref.ref(workspace)`，在 GB300 (`S=261,393` tokens, `4` 文档) 非重入激活重算下，每层前向结束后滞留的临时工作区显存从 **`4,482.1 MiB` (`H=4`) / `17,926.0 MiB` (`H=16`) 降至 `0.0 MiB`（`100%` 消除）**。
  - 将 `KdaWorkspace` 默认改为 `zero_init=False`（`torch.empty`），隐式工作区前反向总延迟在 `H=4` 下从 **`6.48 ms -> 4.66 ms`（`1.391x` 加速，`-28.09%`）**，在 `H=16` 下从 **`26.10 ms -> 18.83 ms`（`1.386x` 加速，`-27.85%`）**，且全 `NaN` 预填充下梯度逐比特一致。
- **Hopper MXFP4 × FP8 MegaMoE 折叠 `K128/N64` 候选（`b17eaa0112`, PR `#6465`）与 Delegated Autotuner（`1de520d5b5`, PR `#6534`）**：
  - 针对 Qwen3.8-Flash-Next（`H=2560, I=640, E=512, EP=2, top_k=10`）中 `640 % 256 != 0` 导致 `K256` 候选全军覆没的问题，新增 `5` 个 `M256/K128` 实测 tactic（含 4 个 `fold_producer_warps=True` 折叠候选），可用候选从 `3 -> 8`。在 `2x H200` 上，`1024` tok/rank 计算耗时下降 **`17.72%`（`593.264 -> 488.128 us`，E2E `-14.93%`）**，`16384` tok/rank 计算耗时下降 **`14.94%`（`5223.024 -> 4442.880 us`）**。
- **SM103a `cake_all_gather_matmul` `_cg2`（`89009ad445`, PR `#7083`）、SM100a NVFP4 SVDQuant Tail-Split（`1eee894ea0`, PR `#7091`）与 CuTe-DSL MegaMOE 持久化 TopK / 128 对齐（`3f398977d7`, PR `#5666`）**：
  - B300 (`sm_103a`) `512×2560` (`K=8192, WS=4` K-major) 路由至 2-CTA `_cg2`，BF16 提速 **`1.0855x ~ 1.0902x`**，FP16 提速 **`1.0767x ~ 1.1143x`**；GB200 SVDQuant 在 `(6912,3072,3072,r=96,b=1)` 提速 **`1.035x`（`30.96 -> 29.92 us`）**。

### 2. Track B：SGLang / TensorRT-LLM / vLLM 推理引擎（`sglang-rust-abort-mm-finalize-trtllm-swiglu-nvfp4-vllm-topk-gdn`）
- **TensorRT-LLM NVFP4 异步输入量化阈值 `ASYNC_INPUT_QUANT_MAX_TOKENS = 1024`（`2676d6ba0a`, PR `#20779`）与 SM100 QuACK SwiGLU 融合（`90d4dcbb8f`, PR `#19773`）**：
  - 修复 GB300 上 DeepSeek-R1 FP4 128K prefill (`PP4`) 因辅助流 `record_stream` 驻留巨型缓冲区引发的 `52` 次阻塞 `cudaFree`（`0.36 s`）与 `2.98 s` PP `SendRecv` 停顿：保持 decode（`<= 1024` tokens）异步、prefill（`> 1024` tokens）主流同步后，Median TTFT 从 **`1,691,192 ms` 降至 `1,198,656 ms`（`-29.12%`）**，Disaggregated 输出吞吐从 **`~460 tok/s` 恢复至 `875.8 tok/s`（`1.904x`）**。
  - PR `#19773` 在 SM100/SM103 上用 QuACK `gemm_act` 将 SwiGLU 融合进 BF16 Gate/Up GEMM epilogue，省去 **80% 的中间激活 HBM 读写**（$M=4096, I=8192$ 单层省 `256 MiB`）与二次 BF16 舍入。
- **vLLM `cooperative_topk` 真实行长分块（`404c2b510e`, PR `#62171`）、CPU GDN Spec-Decode 卷积状态对齐（`f3871c3cbf`, PR `#63339`）与 SGLang Rust Abort 直推（`5a86d6ee17`, PR `#45899`）**：
  - `cooperative_topk` 改用 `ceil(seq_len / CS)` 替代 `ceil(stride / CS)`，使 `40K` 行长在 `256K..1M` 步长下恢复单趟 `48K` staging，B300 内核提速 **`8%`**（`12.18 -> 11.24 us`），4x GB200 GLM-5.3-NVFP4 端到端提速 **`1.5% ~ 2.8%`**。
  - CPU GDN 统一维护 `state_len = conv_kernel + num_spec` 卷积窗口，根除短草稿行 `66%` 输出失真；SGLang Scheduler 在 `--enable-rust-server` 下通过 `rust_server.push_abort` 直推中止事件并新增 `/abort_request` 与多模态 `processor.finalize(&mut entry)`。

### 3. Track C：Megatron-LM / TorchTitan / LMCache / Mooncake / NIXL / Dynamo（`megatron-nvfp4-moe-mfsdp-planes-pad-zero-mooncake-xpu-nof-nixl`）
- **Megatron-LM Per-Token NVFP4 CuTe-DSL MoE（`9314b010da`, PR `#8262`）、MFSDPv2 分阶段 MXFP8 All-Gather（`18bc49d2f6`, PR `#7907`）与 CUDA Graph 动态 Padding 清零（`f9d9bdcc6e`, PR `#8274`）**：
  - GB300 单层 MoE (`H=7168, I=2048, E=256, top_k=8`) 在 `4096` tokens 下从 **`4054.7 us` (BF16) / `3474.3 us` (MXFP8) 降至 `1015.6 us`（`3.99x` / `3.42x` 加速）**；Batch-Invariant 确定性模式下从 **`5006.8 us` 降至 `1107.4 us`（`4.52x` 加速）**。
  - MFSDPv2 在 `FORWARD` 仅 All-Gather `rowwise` MXFP8、在 `BACKWARD` 仅 All-Gather `columnwise` MXFP8，单次 `unshard` 集合通信量降低 **`50.0%`**。
  - Triton 内核 `zero_padding_rows` 从固定设备地址读取 `real_token_count`，在 `2048` tokens 下仅需 **`3.3 us`（比 `masked_fill_` 的 `54.0 us` 快 `16.36x`）**，彻底消除 CUDA Graph partial-batch 重放的 `amax` 污染。
- **NIXL `TELEMETRY_VERSION = 6` 256B 对齐 SPSC 环形缓冲区（`a9f1f7a76f`, PR `#2018`）、Mooncake Intel XPU P2P（`db4f146ecb`, PR `#4379`）与 TorchTitan / LMCache / Dynamo**：
  - NIXL 将 `write_pos` (`[0,8)`) 与 `read_pos` (`[256,264)`) 按 `256B` 隔离并缓存对端游标，同插槽吞吐从 **`11.9 -> 51.9 M events/s`（`4.36x`）**，跨插槽吞吐从 **`2.5 -> 9.2 M events/s`（`3.68x`）**。

## 二、English Executive Summary

### 1. Track A: FlashInfer Blackwell/Hopper Kernel Stack (`flashinfer-megamoe-topk-sm103-ag-svdquant-kda-weakref-mxfp4-k128`)
- **Cake KDA Weakref Checkpointing & `zero_init=False` (`4f88101e60`, PR `#7069`)**: Replacing the strong `ctx.workspace` reference with `weakref.ref(workspace)` eliminates **`4,482.1 MiB` (`H=4`) and `17,926.0 MiB` (`H=16`)** of retained workspace memory per checkpointed layer at `S=261,393` tokens on GB300 (`-> 0.0 MiB`). Defaulting `KdaWorkspace` to `zero_init=False` speeds up implicit-workspace forward+backward by **`1.391x` at `H=4` (`6.48 -> 4.66 ms`)** and **`1.386x` at `H=16` (`26.10 -> 18.83 ms`)**.
- **Hopper MXFP4 × FP8 MegaMoE Folded `K128/N64` Tactics (`b17eaa0112`, PR `#6465`) & Delegated Autotuner (`1de520d5b5`, PR `#6534`)**: Adds 5 `M256/K128` tactics (expanding eligible tactics for `I=640` from `3 -> 8`), cutting `2x H200` compute latency by **`17.72%` at `1024` tok/rank (`593.264 -> 488.128 us`, E2E `-14.93%`)** and **`14.94%` at `16384` tok/rank**.
- **SM103a `cake_all_gather_matmul` `_cg2` (`89009ad445`, PR `#7083`), SM100a NVFP4 SVDQuant Tail-Split (`1eee894ea0`, PR `#7091`), and CuTe-DSL MegaMOE Persistent TopK & 128-Align (`3f398977d7`, PR `#5666`)**: B300 `512x2560` (`WS=4` K-major) `_cg2` achieves **`1.08x..1.11x`** speedup; GB200 SVDQuant `(6912,3072,3072,r=96,b=1)` achieves **`1.035x`** speedup.

### 2. Track B: SGLang / TensorRT-LLM / vLLM Serving Engines (`sglang-rust-abort-mm-finalize-trtllm-swiglu-nvfp4-vllm-topk-gdn`)
- **TensorRT-LLM `ASYNC_INPUT_QUANT_MAX_TOKENS = 1024` (`2676d6ba0a`, PR `#20779`) & SM100 QuACK Fused SwiGLU (`90d4dcbb8f`, PR `#19773`)**: Capping auxiliary-stream NVFP4 input quantization at `1024` tokens eliminates `52` blocking `cudaFree` calls and `2.98 s` PP `SendRecv` stalls on GB300 DeepSeek-R1 FP4 128K prefill, reducing median TTFT by **`29.12%` (`1,691,192 -> 1,198,656 ms`)** and restoring disaggregated output throughput by **`1.904x` (`~460 -> 875.8 tok/s`)**. QuACK fused SwiGLU eliminates **80% of intermediate HBM traffic** (`256 MiB` saved per layer at `M=4096, I=8192`).
- **vLLM `cooperative_topk` Row-Length Sizing (`404c2b510e`, PR `#62171`), CPU GDN Spec-Decode Conv State (`f3871c3cbf`, PR `#63339`), and SGLang Rust Abort Delivery (`5a86d6ee17`, PR `#45899`)**: Sizing `cooperative_topk` by `seq_len` instead of `stride` restores single-pass `48K` staging (`+8%` on B300, `+1.5%..2.8%` E2E on 4x GB200 GLM-5.3-NVFP4).

### 3. Track C: Megatron-LM / TorchTitan / LMCache / Mooncake / NIXL / Dynamo (`megatron-nvfp4-moe-mfsdp-planes-pad-zero-mooncake-xpu-nof-nixl`)
- **Megatron-LM Per-Token NVFP4 CuTe-DSL MoE (`9314b010da`, PR `#8262`), MFSDPv2 Phase-Specific MXFP8 Planes (`18bc49d2f6`, PR `#7907`), and CUDA-Graph Padding Zeroing (`f9d9bdcc6e`, PR `#8274`)**: Delivers **`3.99x`** default (`4054.7 -> 1015.6 us`) and **`4.52x`** batch-invariant (`5006.8 -> 1107.4 us`) MoE speedups on GB300 at `4096` tokens, halves MFSDPv2 MXFP8 all-gather volume (**`-50.0%`**), and zeroes dynamic padding rows in **`3.3 us` vs `54.0 us` (`16.36x` faster)**.
- **NIXL `TELEMETRY_VERSION = 6` 256B-Aligned SPSC Ring Buffer (`a9f1f7a76f`, PR `#2018`)**: Boosts same-socket throughput by **`4.36x` (`11.9 -> 51.9 M events/s`)** and cross-socket throughput by **`3.68x` (`2.5 -> 9.2 M events/s`)**.
