## 2. 本次新增组件、实验与核心架构结论（Chinese Summary）

### 2.1 FlashInfer 统一 `cake_gated_act_mxfp8` 门控激活量化、EP8 MegaMoE 单节点 1-Warp 邮箱与融合路由、每形状 Cluster Split-K `cake_router_gemm`、`cake_megamoe_warp_decode` NVFP4 W4A4、Lag-3 交错 `cake_fused_norm_combine` 及 TileLang 目标回退安全
- **双语组件文档**：[中文](../components/flashinfer-gated-act-mxfp8-ep8-megamoe-warp-decode-norm-combine-tilelang.md) · [English](../components/flashinfer-gated-act-mxfp8-ep8-megamoe-warp-decode-norm-combine-tilelang.en.md)
- **确定性实验**：[`experiments/flashinfer_gated_act_mxfp8_ep8_megamoe_warp_decode_norm_combine_tilelang/run.py`](../../experiments/flashinfer_gated_act_mxfp8_ep8_megamoe_warp_decode_norm_combine_tilelang/run.py)
- **第一手源码与关键结论**：
  1. **跨架构统一 `cake_gated_act_mxfp8`（`flashinfer#7305`, `2f911dd314bd`）**：在 `sm_100a`/`sm_103a`/`sm_107a` 统一融合 `SwiGLU`/`GeGLU` 门控激活与 32 元素 MXFP8 E8M0 块缩放到单次 `128B` 向量化读写，在 `T=2048, I=2048` 达到 **SM103 `4.49x`（`12.61 -> 2.81 us`）**、**SM100 `1.50x`（`3.53 -> 2.35 us`）**、**SM107 `1.12x`（`3.25 -> 2.91 us`）**，并在 R200 将持久化网格派发门限收窄至 `T <= 4096`（**`1.22x` `17.9 -> 14.7 us`**）。
  2. **8xB200 EP8 MegaMoE 1-Warp Arrive-Only 邮箱与融合路由（`flashinfer#7300`, `849424bb3763`）**：将 `copy_to_staging` 合入生产者 kernel（`3 -> 1` 拷贝），用 `peer_signal[rank * 8 + dst_rank]` 单 Warp `st.release.sys` + `ld.acquire.sys` 取代全 CTA 系统栅栏，并在 `M <= 16` 时将路由计算内联至 `dispatch`，将 8xB200 CUDA Graph launches 从 `12` 降至 **`9`**（`M=1` **`165.9 -> 153.8 us` `1.08x`**）。
  3. **每形状 Cluster Split-K `cake_router_gemm`（`flashinfer#7287`, `514bb62a9d0b`）与 Warp-Decode NVFP4 / BF16×FP4（`#7292` `10d7e305bb55` & `#7311` `0840f8c2daab`）**：为 `(K, N)=(7168, 128)` 解码 Router GEMM 预置每形状 Cluster Split-K 表，在 GB300 (`M=16, PDL=on`) 达到 **`1.733x`（`6.656 -> 3.840 us`）**；`cake_megamoe_warp_decode` NVFP4 W4A4 在 GB200 (`M=20`) 达到 **`1.289x`（`161.68 -> 125.43 us`）**，GB300 BF16×FP4 `m128` 2-CTA Pair + PDL 达到 **`1.029x`（`10.860 -> 10.552 us`）**；Lag-3 交错 `cake_fused_norm_combine`（`#7285`, `a9d16462739d`）在 8xB200 达到 **`1.018x`（`30.656 -> 30.112 us`）**；TileLang（`tilelang#2860`, `82b2e9b8532a`）优先读取显式 `target.arch` 与 `TILELANG_DEFAULT_TARGET`，消除无 GPU 构建机静默降级 `sm_80`。

### 2.2 SGLang DeepSeek-V4 HiSparse 逐 Token 解码恢复与全量 Prefill 存储、DP-Attention CUDA Graph 分桶对齐、Diffusion IPC 端口隔离及 vLLM 投机解码自适应 `max_num_seqs`、在线 FP8 量化 `reset_prefix_cache` 与 TensorRT-LLM `UnifiedKvCacheSpecs`
- **双语组件文档**：[中文](../components/sglang-hisparse-dsv4-dp-attn-bucket-diffusion-ipc-vllm-spec-autofit-kv-reset-trtllm.md) · [English](../components/sglang-hisparse-dsv4-dp-attn-bucket-diffusion-ipc-vllm-spec-autofit-kv-reset-trtllm.en.md)
- **确定性实验**：[`experiments/sglang_hisparse_dsv4_dp_attn_bucket_diffusion_ipc_vllm_spec_autofit_kv_reset_trtllm/run.py`](../../experiments/sglang_hisparse_dsv4_dp_attn_bucket_diffusion_ipc_vllm_spec_autofit_kv_reset_trtllm/run.py)
- **第一手源码与关键结论**：
  1. **SGLang DSV4 HiSparse 解码逐 Token 恢复与 512 层 Prefill 全量存储（`sglang#45104`, `e8211be0a862`）**：将 `hisparse_coordinator.py` 中脆弱的 `device_indices.numel() % page_size == 0` 替换为 `self.page_size == 1`，并在 `stage_page_async_d2h` 强制逐 Token 分散拷贝（消除 64-token 解码批次污染 `64 × 63 = 4,032` 个邻槽的静默覆写）；同时在 `enable_hisparse` 下为全部 `512` 层（`480` 稀疏 + `32` 稠密）写出 Prefill KV（修复 `480` 稀疏层冷启动缺失）。
  2. **SGLang DP-Attention 分桶对齐（`#46138`, `fa25740748a8`）与 Diffusion IPC 端口隔离（`#46154`, `3fd41d46e835`）**：在 `forward_batch_generation.py` 用全局 `max_bs` 对齐 CUDA Graph 分桶（如 `[29, 17, 21, 12] -> 32` vs 错误的 `sum=79 -> 80`），消除解码 `IndexError`；为每次 `Generator` 分配独立临时 TCP 端口，修复 `ZMQError: Address in use`。
  3. **vLLM 投机自适应 `max_num_seqs`（`vllm#60513`, `82a6f07fa9a0`）、在线量化重置（`#60810`, `92363c8b2259`）与 TRT-LLM `UnifiedKvCacheSpecs`（`#13615` `263656b7d42e` & `#13583` `65c47b82442c`）**：vLLM 将投机解码每序列最坏槽位乘以 `1 + K`（`K=3` 时 `max_num_seqs` 从 `256` 自动收敛至 **`64`**，消除 `1024 > 256` 崩溃）并在 `quantize_model_weights` 后自动 `reset_prefix_cache()`；TRT-LLM 建立 `UnifiedKvCacheSpecs` 单一真值源并修复 EAGLE3 树投机与预留块计算。

### 2.3 FlashAttention-4 Hopper/Blackwell (`SM90`/`SM100`) 5D Ragged TMA `seqlen_k` 硬件清零与 Softmax 全 `-inf` `NaN` 防护、veRL Top-K + Context Parallel 跨 Rank 序列偏移修复及 Mooncake 寒武纪 MLU (`cnlight`) 通信后端
- **双语组件文档**：[中文](../components/fa4-sm90-sm100-seqlenk-tma-nan-guard-verl-topk-cp-pack-mooncake-mlu.md) · [English](../components/fa4-sm90-sm100-seqlenk-tma-nan-guard-verl-topk-cp-pack-mooncake-mlu.en.md)
- **确定性实验**：[`experiments/fa4_sm90_sm100_seqlenk_tma_nan_guard_verl_topk_cp_pack_mooncake_mlu/run.py`](../../experiments/fa4_sm90_sm100_seqlenk_tma_nan_guard_verl_topk_cp_pack_mooncake_mlu/run.py)
- **第一手源码与关键结论**：
  1. **FA4 5D Load-Safe Ragged TMA 硬件越界清零（`flash-attention#2983` `46b1bd4b6b8d`, `#3012` `fd92c6f600be`）与全 `-inf` Softmax `NaN` 守卫（`#3013` `da6fb01fa351`）**：将 4D `ptr_shift=True`（仅对 TMA Store 安全）升级为 5D TMA 描述符，第 3 维大小设为 `seqlen_k`、步长设为 $2^{64} - \text{stride}_r$（64 位无符号回绕将 `row >= seqlen_k` 映射至负坐标 `-1`，触发 TMA 硬件零填充，消除预分配 KV 槽陈旧数据泄漏）；在 `softmax.py` 引入 `stats_valid = (old_max != -inf)`，将全 `-inf` tile 的 `scale` 强制置 `1.0`（消除 `exp2(-inf - (-inf)) = NaN`）。
  2. **veRL Megatron CP 气泡偏移守卫（`verl#8325`, `30a793700e89`）与 FSDP 词表并行两阶段 Top-K 归并（`#8332`, `c04b686a1f28`）**：在 `data_parallel_compute_topk_kl` 仅当 `distill_loss_len_i > 0` 时推进 `pos_offset`（修复 CP=2 下 Rank 0 在气泡槽错误累加 `+256` 导致序列 2 偏移 `704 vs 448` 的跨样本错位），并在 `fsdp_workers.py` 先做词表分片局部 Top-$K$ 再跨 `all_gather` 归并全局 Top-$K$；Mooncake（`Mooncake#1961`, `b4d9081b75fa`）新增寒武纪 MLU (`torch_mlu` / `cnlight`) 分布式 Store 测试矩阵。
