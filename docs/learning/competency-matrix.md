# 能力矩阵：不从文章数推断专家能力

当前学习者掌握状态：**未评估**。研究产出、练习完成与实际操作能力分开。

| 能力 | 可检查证据 | 未通过/待实践的信号 |
|---|---|---|
| 需求翻译 | 模型、context、并发、质量、TTFT/TPOT/SLO 和可用性契约 | 只有“需要几张 GPU”，没有业务分母 |
| GPU 执行解释 | 画 block/SM/warp、寄存器/shared/global 和同步范围 | 将 local memory 当片上资源，将 occupancy 当吞吐 |
| 显存规划 | 权重、KV、训练状态、workspace、分配余量独立账本 | 用权重量化位宽自动替换 KV 位宽 |
| 瓶颈建模 | 单位正确的 Roofline/通信/存储模型及失效条件 | 用理论上界承诺实际 tokens/s |
| 通信与拓扑 | collective 语义、通信量、rank/layout、传输/交换路径 | 把 NCCL、RDMA、IB、NVLink 当同一层 |
| 软件路径分析 | 固定 commit/path、实际读取函数和调用范围 | 仅凭 README 或函数名声称分析实现 |
| 多节点诊断 | profiler/log/计时契约、对照、故障分类 | 没有区分 socket fallback 与 RDMA、负载不均与拥塞 |
| 训练/推理架构 | 并行/分片/调度、质量、SLO、checkpoint/恢复 | 只用平均吞吐忽略 tail/失败 |
| 运维与经济性 | 隔离/兼容/升级、故障域、每有效工作成本、功率约束 | 用 GPU 利用率替代业务效率 |
| 前沿复核 | 原文、对照、失败分母、相反证据、最小复现实验 | 将公告/最高加速比当已交付/普遍收益 |

## 评分原则

每个练习记录：独立回答、单位/假设、反例、可复核产物和反馈。正确解释但未执行可以通过知识项；硬件实践项只能由真实运行证据通过。

不提供虚构的“专家完成率”。文章、程序和台账的自动验证不属于独立人工认证。
